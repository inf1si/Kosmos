# 노트 작업공간

노트의 **작업공간 → 섹션 → 폴더·문서**는 집필실의 **작품 → 섹션 → 폴더·문서**와 같은 탐색·정리 도구를 쓴다. 작품 연결은 선택 사항이며 한 노트를 여러 작품과 연결할 수 있다. 작업공간은 같은 계정 안의 노트 묶음이다. 계정 전체 저장 객체 `Workspace`와는 구분하며 권한·로그인·공개 범위를 새로 나누지 않는다.

## 만들기와 탐색

- **노트 홈**은 모든 작업공간, 고정 노트, 최근 수정, 수집함과 템플릿을 모아 보여준다. 홈의 **새 작업공간** 또는 사이드바 작업공간 카드에서 새 공간을 만든다.
- 사이드바 작업공간 카드는 집필실의 작품 전환 카드와 같은 위치·모양이다. 공간을 고르면 그 공간의 홈과 트리를 연다. 노트 홈 버튼은 계정 전체 홈으로 돌아간다. 검색·참조·최근 목록에서 다른 공간의 노트를 열면 사이드바도 해당 공간으로 바뀐다.
- 새 공간에는 **노트** 섹션 하나가 있다. **섹션 추가**, 섹션 이름 변경·위아래 이동·접기, 폴더·하위 문서 추가, 드래그와 **이동 · 순서 변경**은 기존 집필실 트리 도구를 쓴다. 섹션의 기본 문서 종류는 노트로 고정한다. 공간에는 최소 한 섹션을 유지한다.
- **전체 · 수집함 · 아이스박스**, 태그·연결 작품 필터는 현재 공간의 사이드바 목록에 적용한다. 노트 홈의 최근·수집함은 모든 공간을 모으고, 공간 홈에서는 해당 공간만 보여준다. 폴더/최근 수정순과 홈의 최근/보드 보기 설정은 기존 기기 설정을 공유한다.
- 보드는 섹션별 최상위 폴더와 **폴더 밖**을 열로 보여준다. 전체 홈의 보드는 작업공간·섹션 경로를 함께 표시하며 다른 공간의 열로 카드를 놓아 옮길 수 있다.

공간 이름은 비워 둘 수 있고 **이름 없는 작업공간**으로 표시한다. 이름이 같은 공간도 ID로 구별한다. 현재 선택은 페이지 안에서 유지하며, 노트 주소를 새로고침하면 해당 노트의 공간을 연다. 공간 자체의 선택만 별도 기기 설정으로 저장하지 않는다.

## 이동과 삭제

노트·폴더 트리 메뉴의 **다른 작업공간으로 이동** 또는 노트 머리 **… → 작업공간으로 이동**에서 공간과 섹션을 고른다. 대상 섹션의 최상위 맨 뒤에 넣으며 폴더·상위 노트의 하위 항목도 함께 움직인다. 폴더·문서 ID, 본문, 첨부, 태그, 작품 연결, AI 대화, 수정 시각은 그대로다. 같은 공간 안의 폴더·형제 위치는 기존 트리 이동 도구로 조정한다.

작업공간 카드의 **이름 변경**으로 이름을 고친다. **삭제**는 짧은 확인 후 공간만 없애고 그 안의 섹션·폴더·노트를 기본 작업공간으로 옮긴다. 문서는 휴지통에 보내지 않는다. 합쳐진 섹션이 40개를 넘으면 삭제를 거절하므로 섹션을 먼저 정리한다. 기본 공간은 이름을 바꿀 수 있지만 삭제할 수 없다.

문서·폴더 휴지통은 기존 공유 휴지통이다. 원래 공간·섹션을 기억해 복원하고, 살아 있는 상위 폴더가 이동했다면 그 위치를 따른다. 공간·섹션이 없으면 기본 공간 또는 남은 첫 섹션으로 복원한다. 폴더 전체 복원은 내부 계층도 복원한다. 공간을 삭제해 섹션이 기본 공간에 옮겨져 있다면 그 섹션으로 복원한다.

## 검색·참조·가져오기

**전체 검색**과 Ctrl/Cmd+K는 집필실·노트의 같은 창을 유지한다. **모든 노트** 또는 **노트 작업공간** 아래 특정 공간을 고른다. 결과와 `@` 검색 경로는 작업공간·섹션·폴더를 포함하며, 기본 공간·노트 섹션 하나만 있는 기존 자료의 중복 경로는 생략한다. 이동한 노트의 기존 참조와 백링크는 ID로 유지된다. 작업공간 자체의 `@` 멘션은 추가하지 않는다.

새 노트·노트 홈 템플릿은 현재 선택 공간에 만들고, 집필실의 빠른 메모는 기본 공간의 수집함 맨 앞에 만든다. 선택 공간의 일반 새 노트도 첫 섹션 최상위 맨 앞에 만들며, 폴더·특정 섹션에서 추가하면 해당 위치를 따른다. 노트 가져오기는 현재 공간의 첫 섹션에 폴더를 만든다. 사용자 템플릿은 현재 공간에서 선택한 하위 구조를 저장하고 선택한 공간·섹션에 적용한다. 휴대 가능한 노트 템플릿은 기존 단일 섹션 형식을 유지하므로 여러 섹션의 문서를 함께 저장하면 선택한 노드의 부모·형제 구조를 단일 섹션으로 모은다. 원본은 그대로다. 폴더를 새 작품으로 만드는 기능도 각 공간에서 사용할 수 있다.

## 저장·호환성

본문은 기존 `Workspace.notes[]`에 유지한다. 선택 필드 `noteNavigation.spaces[]`에 공간 ID·이름과 섹션 ID·이름 배열을, 탐색 노드의 선택 필드 `sectionId`에 소속을 저장한다. 섹션 ID는 모든 노트 공간에서 유일하고 부모와 자식은 같은 섹션에 있어야 한다. 기본 공간 ID는 `default`, 이전 노트의 첫 섹션 ID는 `notes`다. JSON과 탐색 형식 버전은 1을 유지한다.

기존 노트는 ID·폴더·부모·형제 순서를 바꾸지 않고 기본 공간에 표시한다. 읽기만으로 클라우드를 쓰지 않으며 다음 편집·정리 저장에서 구조를 명시한다. 계정 전체 노트 5,000개·노트와 폴더 7,500개·깊이 24단계 한도는 공유한다. 작업공간은 100개, 공간당 섹션은 40개다.

전체 ZIP·서버/Drive/DB 백업·복구 이력은 새 구조를 포함한다. 새 필드가 명시된 백업은 그 구조를 복원한다. 공간 정보가 없는 이전 백업은 같은 ID의 현재 공간·섹션을 보존하고 이전 본문을 복원하며, 다른 섹션을 가리키게 된 부모는 해당 섹션 최상위로 옮긴다. 노트 탐색 정보 자체가 없는 이전 백업의 기존 보존 계약도 유지하며, 노트가 빈 이전 백업에도 현재 공간 이름·섹션은 남긴다. 명시적 새 구조를 이전 백업으로 오인해 덮어쓰지 않는다.

DB의 `guard_note_spaces`는 공간 정보가 있는 저장본을 이전 탭이 누락시키는 저장을 거절하고 공간·섹션·부모 소속을 검사한다. 기존 노트 구조·AI 대화·휴지통 보호와 RLS는 유지한다. 거절된 탭은 새로고침한다. 저장은 기존 낙관적 버전 검사·기기 사본·재전송·충돌 처리 경로를 쓴다.
