## 목표 설계와 다른 중요한 점

- 목표는 장면별 서버 저장이지만 **현재는 작가의 모든 작품을 포함한 작업 공간 JSON 하나**를 저장한다. 다른 문서끼리 수정해도 충돌할 수 있다. 서버 입력 한도는 JSON 텍스트 기준 20,000,000바이트다.
- `chapter`는 부·장 정보를 담는 문자열이다. 부·장·폴더를 별도 객체로 관리하지 않는다. 공개 회차·예약 연재 엔티티도 없다.
- 공개 설정은 `publicSummary` 텍스트다. 비공개 설정의 리치 본문과 독립된 공개 위키 문서 전체를 편집하는 구조는 아직 아니다.
- 공개 페이지는 동적 조회와 `no-store`를 사용한다. 목표 문서의 공개 페이지 캐시·게시 시 캐시 갱신은 미구현이다.
- UI는 Tailwind와 Radix를 사용한 자체 구성 요소다. shadcn/ui 템플릿을 설치한 상태는 아니다.
- 브라우저 복구 이력과 서버 `workspace_revisions`는 별도다. 복구 UI·ZIP은 현재 브라우저의 이력을 사용하며 서버 이력 전체를 자동으로 내려받지 않는다.
- 이미 열린 집필실의 텍스트는 연결 중단 시 기기에 보존한다. 첨부 업로드 대기열, 오프라인 재실행, 브라우저 종료 후 업로드는 없다.

## 운영 전 보완·확인할 항목

1. 작가 로그인·서버 저장·변경 반영·첨부 업로드·샘플 게시와 익명 제한은 확인했다. 다른 기기의 첨부 다운로드, 오프라인 동시 수정·충돌과 ZIP 파일 복원은 추가 검증한다.
2. 장편 원고 규모에 맞춰 문서별 저장과 변경 문서 중심 충돌 화면을 구현한다. 현재 충돌 대화상자는 첫 작품의 일부만 보여주므로 전체 차이 비교 화면이 아니다.
3. [Drive 연결](service-connection.md) 후 첫 실제 백업·다운로드·별도 환경 복원·다음 날 일정 실행을 확인한다. Drive 연결과 백업 성공 기록을 확인했다. 자동 삭제는 없으며 실행 감시 코드와 실제 알림 수신은 별도로 확인한다.
4. 이력 가져오기 직후 최근 50개 제한을 적용하도록 보완했다.
5. 복원 시 같은 첨부 ID의 로컬·클라우드 바이트 차이를 검사하도록 보완했다.
6. RPC는 권한·버전·크기·기본 구조를 검사한다. 전체 문서 구조에 대한 클라이언트 Zod 수준의 서버 검증은 후속 보강 대상이다.
7. 한글 IME, 장편 용량, 다양한 실제 모바일 기기는 별도 사용 검증이 필요하다. 브라우저 자동화가 모든 입력 환경을 검증한 것은 아니다.

초기 운영 ZIP의 별도 파일 저장은 브라우저 도구가 전달하지 못했다. 2026-10-02에는 실제 Drive ZIP을 서버에서 다운로드하고 임시 IndexedDB에 작품·문서·이력·첨부를 복원해 내용과 해시가 일치함을 확인했다. 별도 파일 저장 경로는 확보하지 못했고 전체 DB·Auth·Storage 복원 훈련은 남아 있다.

## 검증과 서비스 상태

0.2.1의 TypeScript 검사, 운영 빌드와 28개 자동 테스트가 통과했다. 초기 10개 브라우저 흐름에 더해 외부 문서 미리보기·추가·내보내기 생성과 기존 ZIP의 로컬 복원을 확인했다. 이후 실제 Supabase 대시보드에서 최초 스키마를 설치하고 익명 REST 접근 검사 7개를 통과했다. 세부 조건은 [검증 기록](../VERIFICATION.md)을 따른다. 실제 작가 원고와 AI 제공자에는 접근하지 않았다.

공개 홈페이지·데이터 이용 안내 추가 후 TypeScript 검사·운영 빌드와 로컬 브라우저를 확인했다. 소스 `41114a1`의 Vercel Production 배포가 32초에 Ready가 됐고 운영 `/`·`/privacy`의 내용·연결을 확인했다. 이 소스 배포와 이후 문서만 변경한 커밋의 배포 확인은 구분한다.

Google OAuth 앱·웹 클라이언트는 사용자가 만들었고 새 비밀키 보관·기존 키 비활성화를 확인했다. 2026-10-02에 실제 공개 URL·도메인과 `drive.file`을 저장했으며 앱은 프로덕션 단계다. 첫 교환의 `invalid_grant` 보고 후 사용자가 재승인·Refresh token 보관 완료를 보고했다. 토큰 값·필드는 읽지 않았으며 완료는 사용자 보고 기준이다. 사용자는 Vercel Production의 Google 연결 변수 3개를 입력·저장했다고 보고했다. 사용자는 서버 변수 4개 저장·재배포를 보고했고, 운영 집필실에서 오늘 Drive 백업 기록과 새 수동 백업·업로드 파일 검증 완료를 확인했다. [준비 결과](evidence/oauth-preparation-2026-10-02.json).

운영 URL은 [kosmos-ashy.vercel.app](https://kosmos-ashy.vercel.app)이다. 시험 게시를 비활성화해 공개 서재는 현재 비어 있다. 로컬 미리보기는 `http://127.0.0.1:3210/studio`다. 이 주소는 개발 서버가 켜져 있는 해당 컴퓨터에서만 동작한다.

화면 이름 Orbis Tertius·소개 문구 제거, 함수 icn1, 백업 파일 다운로드·별도 IndexedDB 복원 시험, 36시간 초과 경고와 Healthchecks 신호, R2 암호화 DB·첨부 workflow를 추가했다. 타입·28개 테스트·운영 빌드를 통과했다. DB cron은 첫 복원 훈련 후에만 켠다. 소스 `88f4010`의 Vercel 배포와 운영 Drive ZIP 다운로드·기기 복원 시험을 확인했다. R2 활성화·비공개 버킷 생성과 30일 보호 잠금은 완료했지만 업로더 인증·실제 DB 백업·DB 복원·알림 수신은 [추가 절차](disaster-recovery.md)에 기록한다. Yjs/DO와 Reader ISR은 후속 migration이다.


## 2026-10-02 백업 보관 정책 확정

사용자가 영구 삭제를 원하지 않아 R2 완료 백업의 자동 만료를 적용하지 않는다. 준비한 만료 양식은 저장하지 않고 취소했고, 일별·월별 경로에 각각 30일 삭제·덮어쓰기 보호만 저장했다. 잠금 기간 뒤에도 파일은 남는다. 저장량 상한 9GB 초과 예정 시 새 업로드를 중단하는 기존 코드와 실패 신호를 유지한다. R2 접근 키·실제 DB 복원·외부 알림 수신은 남은 항목이다.


## 2026-10-02 R2 연결 값과 로컬 암호화 키

사용자가 R2 키 두 값을 메모장에 보관하고 GitHub에 직접 저장했다. 값은 읽지 않고 R2_ACCESS_KEY_ID·R2_SECRET_ACCESS_KEY 이름의 존재를 확인했다. 계정·버킷·암호화 공개키·Supabase 공개 URL도 GitHub에 등록했다. 공식 age v1.3.2 SHA-256 확인, 로컬 키 생성과 합성 파일 암호화·복호화 비교를 통과했다. 개인키는 소스 밖에 보관했고 다른 장소 사본은 미확인이다. 실제 Supabase 서울·Postgres 17.11.0.002·Session pooler 5432를 확인했다. Direct 호스트의 실제 .supabase.co 형식도 허용하도록 백업 스크립트를 수정하고 타입 검사와 해당 백업 테스트 3개를 통과했다. DB 인증 두 값과 감시 URL, 실제 R2 업로드·DB 복원은 아직 남아 있다.
