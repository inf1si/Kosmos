# 제품 요구사항과 집필 방향

## 사용자의 원래 요청

개인 작가가 한 사이트에서 원고를 쓰고, 준비된 작품을 공개하고, 작품마다 구분된 설정집을 운영한다. 집필실은 Muvel·Novela·Pensiv처럼 문서가 많아도 탐색·비교·참조할 수 있는 수준을 지향한다. 대상은 한국어 SF 중단편과 장편 출판소설이다.

공개 독서는 책을 읽는 듯한 깔끔한 화면을 원한다. 각주는 호버로 읽고 클릭하면 해당 위치로 이동하며 본문으로 돌아갈 수 있어야 한다. 본문의 특정 용어는 작품의 설정집과 연결된다. 설정집은 위키의 검색·분류·문서 연결을 사용하되 작품별 범위를 구분한다. AI는 집필과 검토를 보조한다. 클라우드 동기화와 백업도 요구사항에 포함한다.

## 제품의 우선순위

1. **원고 보존:** 저장 실패·오래된 창·복원 때문에 현재 원고가 조용히 사라지지 않는다.
2. **집필 흐름:** 현재 원고를 두고 설정·앞 장면·메모를 찾아 비교한다.
3. **공개 통제:** 작업본 변경은 이미 공개한 작품을 바로 바꾸지 않는다.
4. **독서 경험:** 본문을 중심에 두고 각주와 설정을 필요할 때 읽는다.
5. **작품 구분:** 검색·설정 연결·AI 자료 범위는 현재 작품에 한정한다.
6. **이동 가능성:** 원고와 관계·첨부를 서비스 밖에서도 보관하고 다시 가져올 수 있다.

## SF 출판소설에 맞추는 방식

- **장면과 공개 분량을 구분한다.** 집필은 장면의 목적과 서사 순서를 따른다. 회차 분량에 맞춰 처음부터 원고를 고정하지 않는다. 현재 게시 최소 단위는 장면이다.
- **서술 순서와 작중 시간을 구분한다.** 현재 장면 속성에 시점 인물, 작중 시간, 요약을 기록한다. 이후 시간선과 인물의 지식 시점을 구조화한다.
- **과학 사실과 작품 규칙을 구분한다.** 설정·메모에 기술의 가능 범위, 비용·제약, 리서치 근거를 남긴다. 전용 속성·출처 도구는 후속 범위다.
- **비공개 설정과 독자용 설명을 구분한다.** 반전이나 결말을 집필 자료로 기록해도 공개 설명은 작가가 별도로 작성한다.
- **AI가 문체를 일괄 교체하지 않는다.** 짧은 제안을 근거와 함께 보여주고 선택 적용한다. 장편의 정합성 검토는 보조 의견으로 다룬다.

## 사용자와 화면

| 사용자 | 주요 화면 | 작업 |
|---|---|---|
| 작가 1명 | `/studio` | 집필, 설정·메모, 비교, 게시, 백업·복원, AI 검토 |
| 익명 독자 | `/library` | 공개 작품 발견 |
| 익명 독자 | `/read/[workId]` | 본문·목차·각주·설정 미리보기 |
| 익명 독자 | `/wiki/[workId]` | 그 작품의 공개 설정과 등장 위치 |

사이트 루트 `/`는 현재 집필실로 이동한다. 작가 소개·대표 작품을 갖춘 공개 홈과 별도 작품 소개 페이지는 후속 개발이다.

## 디자인 기준

공개 사이트의 기본 방향은 **문학 서재**다. 타이포그래피, 본문 폭, 여백, 작품 제목의 위계로 책과 서재의 인상을 만든다. SF 아카이브 방향은 설정집 표현의 후보로 남긴다. 최종 브랜드·작가명·표지는 미정이다.

집필실은 문서 탐색과 작업 밀도를 우선한다. Novela의 탐색·간격, Muvel의 분할·보조 도구, Pensiv의 원고·플롯·설정 관계를 참고한다. 원고·설정·메모를 나란히 다루는 실제 작업을 기준으로 개선한다. 참고 제품과 기능이 완전히 같다는 의미는 아니다.

데스크톱·노트북을 집필의 주 기기로 삼는다. 휴대폰은 독서·메모 중심이며 기본 편집을 제공한다. 페이지 넘김 애니메이션보다 안정된 세로 읽기와 본문 복귀를 먼저 구현한다.

## 출시 범위와 제외 범위

첫 운영 범위는 작가 로그인, 편집·저장·복구, 작품별 설정, 선택 게시, 독서, 전체 백업이다. AI는 기본 저장·복원 검증 이후 연결한다.

독자 회원가입, 결제, 댓글·커뮤니티, 공동 집필, 팬 위키 수정, 예약 연재, 실시간 협업, 여러 작품의 공통 세계관은 초기 범위에 포함하지 않는다. DOCX/EPUB와 장편 전체 검토는 사용 후 확장한다.

## 아직 결정하지 않은 것

사이트명·작가명·도메인, 첫 공개 작품, 실제 원고 가져오기 형식, AI 제공자·모델·월 예산, 운영 플랜, 외부 백업 저장소와 보관 기간은 미정이다. 플랫폼 구성은 Next.js + Vercel + Supabase를 기준으로 진행한다.

목표 기능의 상세 내용은 [제품 설계](product-spec.md), 현재 구현과의 차이는 [구현 상태](status.md), 다음 단계의 완료 기준은 [로드맵](roadmap.md)에 기록했다.
