# 백업·복구와 원고 이동

전체 ZIP·이력·Drive ZIP·DB 백업에는 noteNavigation(폴더·노트 부모·형제 순서)과 aiMessages를 포함한다. 계층·AI 필드가 없는 이전 백업은 공통 ID 노트의 현재 정리·기록을 유지하고 새 노트를 최상위로 보충한다. 명시된 필드는 빈 배열을 포함해 복원한다. 본문·메타데이터 외 별도 형식 버전 변경은 없다.

## 휴지통과 삭제 복구

**폴더 전체 삭제**는 하위 문서·노트를 각각 기존 휴지통 항목으로 보관하며 선택 필드 `folder.nodes`에 계층·형제 순서를 함께 저장한다. 휴지통의 폴더 한 줄을 복원하면 폴더·하위 폴더·문서/노트를 원래 계층과 순서로 돌려놓는다. 구조 필드가 없는 이전 항목은 폴더 하나에 모으고, `folder`도 없으면 낱개로 복원한다. 삭제 전 복구 지점(**폴더 전체 삭제 전**·**노트 폴더 전체 삭제 전**)은 당시 전체 작업 공간을 되돌려 이후 다른 편집도 되돌아간다. ZIP/DB 형식 버전과 휴지통 항목 종류는 그대로다.

전체 ZIP은 폴더 구조도 왕복 보존한다. 무결성 해시가 맞더라도 중복 ID·잘못된 루트/부모·순환·24단계를 넘는 구조는 작업 공간 검증에서 가져오기를 거절한다. 같은 검증을 복구 이력에도 적용하며 원본 자료를 변경하지 않는다. [복원 계약](workspace-trash.md#저장호환성).

**휴지통 → 복원**은 노트·작품 문서 한 항목의 본문·AI 대화·첨부·원래 위치를 복원하며 이후 다른 편집을 유지한다. 자동 삭제는 없다. 영구 삭제 전에 현재 브라우저에 **휴지통 영구 삭제 전** 이력을 만들고 저장 실패·준비 중 작업 변경이면 삭제를 멈춘다. 해당 이력에서 **선택한 원고 복원**을 누르면 당시 전체 작업 공간을 복원하므로 이후 다른 편집도 되돌아간다. 이력은 최근 50개·현재 브라우저의 보관 한도를 따른다.

전체 ZIP·Drive ZIP·DB 백업은 `Workspace.trash`와 참조 첨부 바이트를 포함한다. 읽기 사본은 `text/trash/<UUID>.md`다. trash 필드가 빠진 이전 백업은 현재 휴지통과 필요한 첨부를 보존하되 같은 ID가 활성 문서/노트로 복원되면 중복 항목을 제거한다. 명시적 trash 배열은 빈 배열을 포함해 정확히 복원한다. 영구 삭제도 Blob/Storage·기존 이력·이미 내보낸 ZIP/Drive 파일·공개 판본을 지우지 않는다. [휴지통 계약](workspace-trash.md).

## 독립 노트 보존

전체 ZIP·복구 이력·Drive 서버 작업본 백업은 작품 밖의 개인 노트, 태그, 수집함/아이스박스, 작품 연결과 원본 첨부를 포함한다. ZIP의 text/notes/에 읽기 사본도 만든다. 이전 백업에 notes 필드가 없으면 현재 노트·첨부를 보존하고 복원본에 없는 작품 관계만 정리한다. 명시적 notes 배열이 있으면 백업의 노트를 복원한다. [사용법과 제한](personal-notes.md).

백업 구현은 [backup.ts](../src/lib/backup.ts), 실제 파일 확보와 복원 흐름은 [studio-provider.tsx](../src/components/studio-provider.tsx)에 있다.

## 서로 다른 보존 수단

| 수단 | 현재 동작 | 복구할 수 없는 경우·경계 |
|---|---|---|
| 기기 자동 저장 | IndexedDB의 최신 작업본 | 기기·브라우저 데이터 소실 |
| 기기 복구 이력 | 수동, 게시·복원·AI 적용 전, 집필실이 열린 동안 약 10분 간격 | 같은 기기에 있으므로 독립 백업 아님 |
| 서버 작업본·이력 | Supabase 연결 후 최신 작업본, 저장 시 약 10분 간격 이전 작업본 | 실제 최신 작업본 저장 확인. 서버 이력은 현재 복구 UI에 미연결 |
| 전체 ZIP | 작가가 원고·관계·이력·실제 첨부를 내려받음 | 내려받은 뒤 수정한 내용은 포함하지 않음 |
| Supabase 운영 백업 | 선택한 플랜·설정에 따름 | 아직 미설정. DB 백업에는 Storage 파일 바이트가 없음 |
| 독립 저장소 자동 백업 | Google Drive(선택) 및 S3/R2 서버 어댑터, 일일 일정·저장 후 검증 | 운영 Drive 업로드·재다운로드·임시 IndexedDB 복원 확인. R2 전체 DB 저장·복원 미완료 |

동기화는 최신 상태를 맞추는 기능이다. 같은 실수나 손상도 전파될 수 있어 별도의 이력·백업이 필요하다.

## ZIP 구조

```text
Orbis-Tertius-전체백업-2026-10-02.zip
├─ manifest.json        형식·파일 경로·크기·SHA-256
├─ workspace.json       현재 원고·설정·주석·관계·판본의 복원 원본
├─ revisions.json       기기 복구 이력의 작업 공간 사본
├─ assets/<UUID>        현재 및 이력에서 참조한 실제 이미지 바이트
├─ text/<작품 UUID>/<문서 UUID>.md
└─ README.txt
```

파일 이름의 날짜는 만든 날(UTC)이다. 복원은 이름이 아니라 `manifest.json`과 내용으로 확인하므로 이전 이름(`궤도서재-전체백업-날짜.zip`)으로 받은 ZIP도 그대로 복원한다.

`text/`는 제목과 일반 텍스트를 읽기 쉽게 남긴 사본이다. 서식·각주·설정 연결을 완전히 표현하지 않으므로 원본 JSON을 대체하지 않는다. 파일 확장자가 없는 `assets/` 항목의 타입·이름은 JSON의 메타데이터로 복구한다.

클라우드 모드에서는 기기에 없는 현재·이력 첨부를 Storage에서 내려받은 후 ZIP에 넣는다. 첨부를 확보하지 못하면 누락된 ZIP을 성공으로 처리하지 않는다. ZIP에는 비공개 원고도 포함한다.

## 내보내기

1. 사이드바의 **백업과 복구**를 연다.
2. **작품 전체 ZIP 백업** 영역의 **백업 내려받기**를 실행한다.
3. 생성된 **파일 저장** 링크를 눌러 실제 ZIP을 내려받고 다른 디스크나 선택한 저장소에 보관한다.
4. 중요한 변경·실제 원고 이동·배포 환경 전환 전에는 새 ZIP을 만든다.

화면의 마지막 파일 생성 시각은 ZIP 생성이 완료된 시각이다. 사용자가 파일을 보관했는지, 외부 저장소 전송을 완료했는지까지 확인한 값은 아니다. ZIP은 암호화하지 않는다. 파일 접근 권한은 보관할 저장소에서 관리한다.

## 복원

1. **백업과 복구**에서 ZIP을 선택한다.
2. 형식·파일 크기·SHA-256·모델·첨부 연결 검사 결과와 작품·문서·첨부 수를 확인한다.
3. **백업 복원**을 실행한다. 현재 작업 공간을 복구 이력에 남긴 뒤 백업의 작업 공간으로 바꾼다.
4. 복원된 원고와 각주·설정 링크·첨부를 확인한다. 클라우드 모드라면 동기화 완료도 확인한다.
5. 가져온 이력은 기존 이력과 합친 즉시 최근 50개로 정리된다. 원하는 복구 지점이 남았는지 확인한다.

복원은 특정 장면만 합치는 기능이 아니다. 전체 작업 공간을 교체한다. 가져온 이력의 ID는 새로 부여한다. 같은 로컬 또는 클라우드 첨부 ID에 다른 바이트가 있으면 현재 원고를 유지하고 복원을 중단한다.

클라우드 첨부는 원고 교체 전 필요한 파일을 업로드한다. 중간 실패 시 현재 작업본은 유지되지만 먼저 올라간 미참조 첨부가 남을 수 있다. 원격에 같은 ID가 있으면 실제 바이트를 대조하며 다를 때 중단한다.

**클라우드 작업본 복원은 이미 게시된 판본을 바꾸지 않는다.** 공개 내용을 바꾸려면 다시 게시한다. 기기 미리보기에서는 전체 작업 공간 안의 미리보기 판본도 백업 상태로 돌아간다.

## 무결성 검사와 한도

- 압축 ZIP 파일은 100MiB 이하, manifest에 기록한 압축 해제 내용 합계도 100MiB 이하다.
- manifest는 최대 3MiB, 목록 항목은 최대 12,000개, ZIP 엔트리는 최대 14,000개다.
- 상대 경로, 중복 목록, 누락, 크기, 해시, Workspace 형식, 현재·이력 첨부를 검사한다.
- 복구 이력 형식은 최대 50개를 허용한다. 복구 지점 생성과 백업 가져오기 시 초과 이력을 정리한다.
- 실제 첨부는 PNG/JPEG/WebP, 각각 10MiB 이하다.

SHA-256 검사는 파일 손상·변조를 발견하는 수단이며 작성자 인증 서명은 아니다. JSON 형식 버전이 달라지면 변환 절차가 필요하다. 잘못된 백업을 읽기 위해 검사를 임의로 끄지 않는다.

## 기기·도메인·로그인 전환

미리보기 원고를 로그인 작업 공간으로 옮기려면 **미리보기에서 ZIP 내보내기 → 로그인한 집필실에서 ZIP 복원** 순서다. 로그인만으로 기존 기기 샘플 원고를 자동 업로드하지 않는다.

로컬 주소에서 Vercel 주소로 옮기는 경우도 origin이 달라 기기 데이터가 자동 이동하지 않는다. 같은 Supabase 계정의 서버 확인된 원고는 로그인으로 가져오고, 미전송 로컬 원고는 ZIP으로 옮긴다.

## 독립 백업과 외부 문서 이동

사용자는 Google Drive 무료 공간을 선택했다. 서버가 클라우드 작업본·이력·참조 첨부로 전체 ZIP을 만들고 매일 04시대에 보관하는 코드를 구현했다. 실제 저장된 ZIP 검증 후에만 성공 시각을 남긴다. OAuth·서버 연결과 운영 업로드·재다운로드·임시 IndexedDB 복원을 확인했다. 별도 파일 저장·실제 다른 기기 복원은 추가 확인한다. [자동 백업](offsite-backup.md)과 [연결 순서](service-connection.md)를 따른다.

충돌 대화상자의 **양쪽 원고 백업 만들기**는 현재 원고와 다른 원고(이력)를 하나의 ZIP으로 생성한다. 선택 전에 파일을 보관할 수 있다. 첨부 확보 실패는 오류로 표시한다.

Notion·Evernote 등으로 이동할 때에는 [문서 교환](import-export.md)을 사용한다. MD/HTML/ENEX는 전체 백업을 대체하지 않는다. 공급자 DB 백업과 첨부 범위는 [Supabase 공식 안내](https://supabase.com/docs/guides/platform/backups)를 확인한다.


## AI 프리셋 복원

전체 ZIP은 라이브러리·선택을 포함한다. 이전 백업에 필드가 없으면 현재 라이브러리를 유지하고 있으면 백업 설정을 복원한다. 복원 직전·사용자 프리셋 삭제 전 복구 지점을 남긴다. API 키는 ZIP에 없으므로 별도로 연결한다. MD/HTML/ENEX 문서 교환에는 계정 설정을 넣지 않는다.

## 사용자 속성·템플릿 백업

전체 ZIP, Drive 백업과 복구 지점은 `customProperties`와 `templates`, 템플릿 소속 첨부 바이트를 포함한다. 템플릿 적용 전·삭제 전에 전체 복구 지점을 만들며 복원하면 당시 작업 공간 전체로 돌아간다. 이전 백업에 새 필드가 없으면 현재 템플릿·필요 첨부와 같은 ID 문서의 사용자 속성을 보존한다. 명시적인 빈 배열은 삭제 상태로 처리한다. 선택 문서 MD/HTML 교환은 속성과 빈 제목을 보존하지만 템플릿 목록을 포함하지 않는다. [사용법](workspace-templates.md#삭제복구저장).

## 서재 순서 백업

운영의 작가 지정 순서는 공개 테이블 `library_position`에 별도로 저장한다. 작업 공간 ZIP·Drive 백업·기기 복구 지점 복원은 이미 게시된 판본과 운영 순서를 바꾸지 않는다. 데이터베이스 재해 복구 덤프에는 새 열이 포함된다. 기기 미리보기의 `Publication.libraryPosition`은 전체 작업 공간에 포함되어 백업·복원되며 기존 백업에서 필드가 없어도 계속 읽는다. 독자의 `kosmos-library-sort`는 기기 보기 설정이므로 작업 공간 백업에 넣지 않는다. [서재 순서](library-order.md).

## 집필실 책장 백업

전체 ZIP·Drive ZIP·DB 백업·복구 이력은 `Workspace.workShelves`의 이름·순서·작품 위치를 포함한다. 책장 필드가 없는 이전 백업은 현재 책장을 보존하고 복원본에도 남은 작품 ID만 유지한다. 명시적 배열은 그대로 교체하고 빈 배열은 기본 책장으로 초기화한다. 휴지통 작품의 책장도 함께 보관하며 영구 삭제한 작품 참조는 제거한다. 접힘은 기기 보기 설정으로 백업하지 않는다. 선택 문서 MD/HTML 교환·공개 판본에는 책장 목록을 넣지 않는다. [책장 사용법](work-shelves.md).
