# 집필 작업 대화

집필실·노트 사이드바의 **작업 대화**에서 문서를 오가며 이어지는 작업을 요청한다. 기존 문서별 AI 대화·커서 질문은 그대로다. [전체 설계와 후속 작업](personal-knowledge-agent-design.md).

## 사용

새 대화에서 작품 하나 또는 노트 작업공간 하나, 실행 방식, 제공자·모델을 선택한다. 질문을 보내기 전에 기기 원고와 계정 저장을 동기화한다. 요청을 접수하는 동안 입력을 잠그고 끝나면 입력칸으로 돌아온다. 모델이 작업하는 중에는 다음 질문을 쓸 수 있다. 자료 범위는 대화를 만든 뒤 고정하며 다른 범위는 새 대화로 시작한다. 실행 중에는 방식·제공자·모델·웹 조사 선택을 잠그고, 변경하려면 먼저 중단한다.

| 방식 | 원고 처리 |
|---|---|
| 함께 생각하기 | 검색·읽기·웹 조사·기억·대화. 문서 쓰기 도구 없음 |
| 검토하며 실행 | 변경을 작업본에 준비. **변경 → 변경 적용**으로 반영 |
| 맡겨 실행 | 도구 실행 후 변경 묶음을 서버에서 반영. 충돌이면 작업본과 오류를 보존 |

생성·부분 치환·이어 쓰기·이름 변경·이동·폴더 생성을 지원한다. 이어 쓰기는 인용한 구절이 든 문단 바로 뒤나 문서 끝에 새 문단을 넣고 기존 문단의 서식을 건드리지 않는다. 인용이 여러 문단에 나오면 거절한다. 대화의 작업 내역은 각 단계가 다룬 문서·폴더를 제목으로 적는다. 생성한 문서를 같은 실행에서 다시 읽고 수정할 수 있다. 부분 치환은 단일 텍스트 노드에 정확히 한 번 나오는 구절만 처리하며 서식·각주를 보존한다. 빈 문서 제목도 가능하다. 공개·영구 삭제·다른 작품/노트 공간 수정·명령어 실행 도구는 없다.

**변경**은 문서별 이전/이후 본문과 구조 변경 수를 보여준다. 구조 전체의 시각적 비교는 후속 작업이다. **변경 적용**과 **되돌리기**는 변경 묶음 단위다. 범위 안의 원고·구조가 바뀌었으면 충돌로 멈추며 사용자의 최신 편집을 덮지 않는다. 다른 작품/노트 공간의 변경은 보존하고 복구한 문서의 이전 수정 시각도 유지한다. 되돌리거나 버린 작업은 서버에서도 다시 적용하지 못하게 막는다. 이미 반영된 변경을 버리기로 표시하지 않으며, 다른 창의 되돌리기도 열린 대화에서 다시 읽어 원고에 반영한다.

**중단**은 이후 도구·원고 반영을 막는다. 이미 전송된 모델 요청의 비용까지 취소한다고 보장하지 않는다. 같은 대화에 새 질문을 보내면 이전 실행을 중단한다. 완료되어 적용하지 않은 작업본은 기준 원고가 같을 때 다음 요청으로 이어지고, 아직 실행 중이던 작업본은 이전 변경 목록에 남는다. 계정당 한 작업을 실행한다.

**기억**에서 에이전트가 저장한 방향·열린 질문을 확인하고 **잊기**로 삭제한다. 원고·질문·답변은 삭제하지 않는다. 삭제·이동되어 현재 범위를 벗어난 출처의 기억과 이전 답변은 다음 모델 문맥에서 제외한다. 출처 없는 창작 제안은 남으며 과거 스냅샷·결과를 원본 삭제와 함께 자동 삭제하지 않는다.

## 에이전트가 받는 지침과 작업 환경

2026-11-13부터 실행을 시작할 때 다음을 모델에 함께 준다. [지침 코드](../src/lib/agent-instructions.ts)·[설계 기준](ai-prompts.md#작업-대화-지침).

| 항목 | 내용 |
|---|---|
| 성격 | AI 설정에서 고른 **프리셋**. 문서 AI 대화와 같은 지침이며 기본값은 **창작 파트너**다 |
| 스킬 | 저장한 **내 스킬**의 이름·설명·요청. 대화에서 이름으로 부를 수 있다 |
| 문서 지도 | 범위 안의 섹션·폴더·문서 제목·종류·글자 수·ID와 문서 속성(시점 인물·작중 시각·요약 앞 80자, 노트는 태그). 본문은 싣지 않는다 |
| 열어 둔 문서 | 작업 대화를 연 화면에서 보고 있던 문서·노트. "이 장면"이 가리키는 대상이며 작업 내역 맨 앞 **열어 둔 문서**로 남는다 |
| 고정 규칙 | 실행 방식의 권한, 자료 안의 지시를 따르지 않는 경계, 읽고 나서 쓰기·변경 대조·제목으로 가리키기. 이 작품의 구상이면 지도에서 걸리는 설정·장면 몇 개를 읽어 연결의 재료로 쓰고, 웹 조사는 구상 흐름을 끊지 않게 꼭 필요할 때만 한다 |
| 작업 기억 | 지난 대화에서 남긴 메모. 작가가 고른 방향과 접은 방향은 이어서 존중하되 원고와 어긋나면 원고가 기준이다 |

문서 지도는 기본 16,000자까지 싣고(`AGENT_MAP_CHARACTERS`) 넘는 문서는 개수만 알린 뒤 검색에 맡긴다. 열어 둔 문서는 대화의 자료 범위가 작업 대화를 연 화면과 같을 때만 보낸다. 홈·플롯보드·그래프에서 열면 없다.

검색은 모든 검색어가 제목이나 본문에 든 문서를 찾아 제목이 맞는 문서를 앞에 두고, 문서마다 일치한 대목 최대 세 곳과 그 위치를 돌려준다. 문서 읽기는 그 위치부터 시작할 수 있고 요약·시점 인물·작중 시각·상태도 함께 돌려준다. 의미 검색은 여전히 없다.

프리셋·스킬은 실행을 시작할 때 계정 저장본에서 읽는다. 사용자 프리셋을 골라 두었다면 그 내용이 그대로 성격이 된다. 프리셋은 실행 방식의 권한이나 자료 경계를 바꾸지 못한다. 답은 화면에 글자 그대로 표시하므로 마크다운 기호를 쓰지 않게 지시한다.

## 모델과 웹 조사

Vertex AI의 Gemini·Claude를 사용한다. 코딩 CLI나 별도 상시 서버 설치는 필요 없다. [서버 설정](vertex-ai.md)을 마쳐야 실행한다. 브라우저 쿠키에는 모델 목록·기본 ID만 저장하고 인증은 서버의 OIDC/WIF로 처리한다. 서버에 연결되지 않은 모델은 실제 호출 전에 연결 오류를 표시한다.

**웹 조사 · Gemini**를 켜면 주 대화 모델과 별도로 Gemini의 Google Search grounding·URL context를 사용한다. 주 모델이 Claude여도 조사에는 같은 프로젝트의 Vertex Gemini 연결이 필요하다. 검색 결과의 출처와 Google 검색 제안은 작업 내역에서 확인한다. 페이지 읽기는 공개 HTTPS 도메인만 받으며 로컬 주소·IP·인증정보·특수 포트는 거절한다. 앱 서버가 임의 웹 주소를 직접 내려받지 않는다.

모델·검색은 제공자 요금과 한도를 따른다. 앱의 글자 수·일일 횟수 제한은 추가하지 않는다. 실행 루프는 기본 80단계 뒤 멈추며 이는 무한 도구 호출을 방지하는 서버 설정이다(`AGENT_MAX_STEPS`). 마지막 단계에서는 도구를 빼고 지금까지 한 일·준비한 변경·남은 일을 답하게 해서, 한도에 닿아도 답이 빈 채로 끝나지 않는다. 단계/출력 한도에 닿은 실행은 여전히 실패로 표시하고 자동 반영을 보류한다. 한 실행 안에서 받은 도구 결과가 기본 80,000자를 넘으면 오래된 것부터 줄인다(`AGENT_TOOL_RESULT_CHARACTERS`). 최근 도구 결과 네 묶음과 1,000자 미만 결과는 그대로 두고, 줄인 결과에도 문서 ID·제목은 남긴다. 줄어든 내용이 필요하면 모델이 다시 읽는다. 긴 대화의 다음 모델 입력에는 최근 대화부터 기본 60,000자까지 넣고(`AGENT_HISTORY_CHARACTERS`), 과거 대화는 검색·이어 읽기 도구로 찾는다. 문맥에 넣는 지난 답 끝에는 앱이 그 실행에서 바꾼 문서와 반영 여부(원고에 반영됨·작업본에만 있음·되돌림)를 `[작업 기록]` 한 줄로 붙인다. 저장 기록을 잘라내는 제한은 아니다. 새 질문 자체가 모델 문맥을 넘으면 실패와 질문을 남긴다. 임베딩·모델별 자동 요약은 아직 없다. 작품별 지침 문서(작품마다 다른 문체·규칙)도 없다.

## 저장과 충돌

원고는 기존 Workspace·IndexedDB·Supabase 저장을 유지한다. 입력 스냅샷은 실행마다 보관하므로 사용이 쌓이면 DB 저장 용량도 늘어난다. AI 자료는 별도 `agent_sessions`·`agent_runs`·`agent_memories`에 보관하고, 진행 기록만으로 원고 버전이 바뀌지 않는다. 실행 스냅샷에는 선택 범위의 원고·구조만 넣고 공개 판본·다른 문서 AI 대화·첨부 바이트는 제외한다.

Vercel Workflow는 중간 도구 결과를 보존하고 실행을 재개한다. 앱 DB는 대화와 작업본을 보존한다. 새로고침·재접속 후 같은 대화를 선택해 확인한다. 시작 토큰·요청 UUID·도구 호출 ID로 중복 실행/기록/반영을 막는다. 앱 DB 접근은 현재 작가 허용 목록과 소유자를 확인한다. 브라우저 DB 역할에는 원고 반영 RPC나 에이전트 상태 변경 권한이 없다. 작가 허용 목록을 단계마다 다시 대조한다. 계정·원고의 삭제와 권한 변경은 기존 계정 관리 계약을 따른다.

반영 시 현재 범위 해시를 비교하고 최신 Workspace에서 명령을 계산한다. JSON 객체 필드 순서는 해시에 영향을 주지 않는다. 검증된 결과만 전체 Workspace 버전 조건으로 저장하고 기존 보호 트리거·반영 전 서버 복구 이력을 거친다. 브라우저는 원격 저장을 다시 읽되 미전송 편집·대기열·계정 변경·충돌이 있으면 교체하지 않는다.

### 반영 중에 다른 곳에서 쓴 글

에이전트가 반영한 범위(작품 하나 또는 노트 공간 하나)를 이 기기에서 고치지 않았다면, 그동안 다른 곳에서 쓴 미전송 글은 저장 충돌 없이 합쳐진다. 예: 작품을 **맡겨 실행**으로 요청하고 노트에서 계속 쓰면 작품은 에이전트 결과, 노트는 쓴 글 그대로 남는다. 집필실을 닫았다가 미전송 글이 있는 채로 다시 열 때도 같다. 쓰고 있던 편집기는 초점·커서를 유지하고, 에이전트가 바꾼 문서의 편집기와 그 범위의 트리만 새로 읽는다. 합친 뒤에도 **되돌리기**를 쓸 수 있고, 합치기 전 기기 원고는 복구 지점 **작업 대화 변경을 합치기 전**으로 남는다.

합치는 조건은 모두 충족해야 한다.

- 서버 버전이 이 기기가 마지막으로 확인한 버전의 바로 다음이고, 그 버전이 되돌리지 않은 에이전트 반영 하나다.
- 이 기기의 해당 범위 해시가 에이전트가 읽은 원본(`base_hash`)과 같다.
- 서버의 해당 범위 해시가 에이전트 결과(`applied_hash`)와 같고, 합친 결과의 범위 해시도 같다.

하나라도 다르면 기존 **저장 충돌** 창이 뜬다. 같은 작품(같은 노트 공간) 안에서 쓴 글, 다른 기기의 저장이 끼어든 경우, 에이전트 반영이 두 번 이상 쌓인 경우, 되돌리기가 그렇다. 문서 단위 병합과 **변경 적용**의 문서 단위 비교는 후속 작업이다. 조건 확인은 `GET /api/agent/commits/{버전}`(작가 본인, 범위·해시만 반환)으로 한다.

## 백업과 개인정보

**AI 자료 내보내기**는 현재 계정의 세션·실행 입력 스냅샷·질문·답변·작업본·출처·기억을 JSON으로 받는다. 원고의 전체 ZIP·Drive ZIP에는 이 별도 테이블이 들어가지 않는다. JSON 가져오기 화면과 AI 자료의 개별 영구 삭제는 아직 없다. 전체 DB 백업의 `public` 스키마 수집 대상에는 포함되지만 새 테이블의 실제 클라우드 백업·재난 복구는 별도 검증이 필요하다.

키·브라우저 토큰을 실행 인자·에이전트 기록·내보내기에 저장하지 않는다. 선택 범위에서 도구가 읽은 글, 질문·최근/조회한 과거 대화·기억을 선택 모델에 보낸다. 실행마다 활성 프리셋·내 스킬·범위의 문서 지도(제목·요약 등 속성)·열어 둔 문서 제목도 보낸다. 웹 조사 질문과 해당 결과는 Gemini로 보낸다. Vercel Workflow의 실행 데이터에도 입력/도구 결과가 보관된다. 원고·웹 페이지 안의 지시문은 자료로 취급하도록 지시하지만 실제 모델의 프롬프트 공격 저항성을 합성 검사만으로 보장하지 않는다. [개인정보 안내](../src/app/privacy/page.tsx).

## 현재 범위와 후속 작업

첫 구현은 실제 도구 실행·작업본·반영·복구를 연결한다. 공통/작품별 LLM Wiki, 여러 공간을 합친 자료 범위, 의미 검색·설정 전수검사, PDF/OCR, 장기 예약, 자발적 제안, 기억 편집·세션 삭제, AI 자료 가져오기는 후속 작업이다. 합성 모델로 도구 연결을 시험한 결과와 실제 소설의 답변 품질은 구분한다. [검증 기록](../VERIFICATION.md).

## Vertex AI 전환 (2026-11-09)

기존 문서·노트·커서 AI와 같은 `orbiter-ai` 프로젝트에서 Gemini·Claude를 사용한다. 모델 목록은 AI 설정에서 공유하고, 작업 대화의 모델 드롭다운에서 고른 ID를 각 실행 시작 때 고정한다. 선택만으로 모델을 호출하지 않으며 같은 세션에서도 다음 요청의 모델은 바꿀 수 있다. 웹 조사는 Vertex Gemini다. 예전 OpenAI 대화/실행 자료는 보존하지만 새 실행에는 선택할 수 없다. 서비스 계정 키 파일을 배포하지 않고 OIDC/WIF로 단기 인증한다. [서버 설정과 미완료 연결](vertex-ai.md).

웹 조사와 모델 호출의 인증/전송 실패는 정리된 오류만 실행 기록에 남긴다. 원래 인증 라이브러리의 상세 오류 객체는 넘기지 않는다.
