# 작품에 속하지 않는 개인 노트

기준: 2026-10-04. 집필실 사이드바의 **노트**에서 작품을 선택하지 않고 생각·관찰·자료를 적는다. 기존 작품의 메모와 별도의 계정 자료다.

## 작성과 찾기

- 노트 공간의 **새 노트** 또는 Alt+N(맥 Option+N)으로 빈 노트를 열고 바로 본문을 입력한다. 제목은 선택 사항이며 비어 있으면 첫 번째 본문 줄을 목록에 표시한다.
- 집필실에서는 상단 **빠른 메모**(StickyNote 아이콘, Alt+N)가 원고 옆 팝오버를 연다. 한 줄이 한 문단이 되며 **수집함에 넣기**(Ctrl/Cmd+Enter)는 화면을 바꾸지 않고 새 노트를 수집함 맨 앞에 저장한 뒤 입력칸을 비운다. **노트에서 열기**는 적은 내용(비어 있으면 빈 노트)을 저장하고 노트 공간에서 연다. Esc는 창을 닫고 원고로 돌아간다. Ctrl/Cmd+Shift+N은 브라우저의 시크릿·개인 정보 보호 창 단축키라 페이지가 받을 수 없어 쓰지 않는다.
- 집필실과 같은 편집기를 사용한다. 글꼴·기기 표시 크기, 저장되는 문자·문단·표 서식, 각주, 실행 취소와 본문 검색을 쓴다. 독립 노트에서 작품별 설정 링크 도구는 비활성이다. 노트 본문은 원고와 달리 문단 첫 줄을 들여쓰지 않고 줄·문단 간격을 좁혀 짧은 메모와 나열을 읽기 쉽게 한다. 글꼴·크기 표시 설정은 집필실과 같다.
- 왼쪽 **전체 노트 검색**은 제목·본문·태그·폴더 이름을 함께 찾으며 여러 검색어를 모두 포함하는 노트를 표시한다. Ctrl/Cmd+K로 검색을 연다. 검색칸 옆 **노트 필터**에서 태그와 연결 작품으로 함께 좁히며, 적용 중이면 버튼에 점이 보이고 **필터 초기화**로 해제한다.
- 새 노트는 **수집함**에 들어간다. 제목 아래 `…`(노트 더 보기) 메뉴의 **아이스박스에 넣기**로 보관하고 **수집함으로 꺼내기**로 다시 꺼낸다. 검색 아래 **전체 · 수집함 · 아이스박스** 보기 버튼 한 줄로 거르며 전체에서는 둘 다 보인다. 목록은 폴더·상위 노트 아래의 형제 순서다. 처음 읽는 이전 목록은 최근 수정 순으로 고정하고 새 노트는 최상위 맨 앞에 둔다.
- **태그 추가**에서 선택적으로 분류한다. 태그가 있으면 칩에 태그 이름(최대 3개와 나머지 개수)이 보이고 누르면 같은 창에서 추가·제거한다. 제목·태그·작품 연결을 입력하기 전에 본문부터 쓸 수 있다.
- `…` → **이미지 첨부**에서 PNG/JPEG/WebP 이미지를 보관한다. 첨부가 있으면 **첨부 n** 칩이 보이고 목록에서 내려받는다. 본문 안 이미지 삽입은 아니며 기존 집필실과 같은 별도 참고 첨부다.

태그·작품 연결·첨부 팝오버는 바깥 Popover의 여백과 높이 제한·스크롤을 공유한다. 내부 목록에 별도 스크롤을 겹치지 않아 태그 입력란의 선택/초점 테두리와 작품 체크박스의 초점 테두리가 잘리지 않는다. Tab으로 이동하고 작품 연결은 Space, 태그 추가는 Enter를 사용할 수 있다. 긴 작품 제목은 체크박스 크기를 유지한 채 줄바꿈하고 긴 목록은 팝오버 안에서 스크롤한다.

## 폴더와 하위 노트

**노트 정리 → 최상위 폴더 추가**로 디렉토리를 만든다. 노트·폴더의 `…` 또는 우클릭 메뉴에서 **하위 노트 추가**, **하위 폴더 추가**, **이동 · 순서 변경**을 쓴다. 하위 노트는 제목 입력 없이 빈 본문으로 바로 열린다. 폴더 이름은 메뉴의 **이름 변경**으로 행 안에서 고친다(Enter 저장, Esc 취소). 빈 폴더만 삭제할 수 있다.

집필실과 같은 손잡이 드래그와 이동 폼을 쓴다. 위/가운데/아래에 놓으면 앞/하위/뒤로 옮기고 **노트 정리** 머리에 놓으면 최상위 맨 뒤로 옮긴다. 이동 폼에서 **노트**는 최상위다. 부모를 옮기면 하위 노트·폴더가 함께 이동하며 본문·태그·수집함/아이스박스·작품 연결·AI 기록은 그대로다. 노트 제목은 본문을 열고 옆 화살표는 하위 목록만 접는다.

**노트 정리 되돌리기**는 마지막 정리 작업 하나를 되돌린다. 그 이후 작성한 본문과 새 노트는 남으며 본문 실행 취소와 별개다. 접힘·정리 실행 취소는 새로고침 후 유지되지 않는다. 폴더와 노트 합계 7,500개·깊이 24단계이며 자기 자신·자손·없는 위치로 이동할 수 없다.

검색·태그·작품·수집함/아이스박스 필터에서도 일치한 노트의 상위 경로를 함께 보여준다. 검색 중에는 경로를 펼치고 드래그를 잠근다. 조건을 해제하면 기존 접힘으로 돌아간다. 폴더 이름 검색은 그 아래 노트도 찾는다. **전체 노트**·수집함·아이스박스는 같은 트리를 보는 조건이며 별도 디렉토리 소속이 아니다. 검색 줄과 보기 버튼 줄 사이에 12px 간격을 둔다.

## 휴지통과 복원

노트 행의 `…` 또는 우클릭 메뉴에서 **휴지통으로 이동**을 누른다. 확인창 없이 해당 노트를 옮기며 하위 노트·폴더는 기존 형제 위치에 남긴다. 마지막 노트도 옮길 수 있다. 본문·태그·작품 연결·첨부·AI 대화를 계정 휴지통에 보관하고 작품 사본은 유지한다.

왼쪽 **휴지통 → 복원**은 해당 항목만 원래 위치로 돌려놓는다. 그 사이의 다른 편집을 덮어쓰지 않는다. 없어진 부모는 최상위로 복원하고 따로 이동한 하위 항목은 새 위치를 유지한다. **영구 삭제**와 **비우기**에만 짧은 확인창을 둔다. 자동 삭제·기간 만료는 없다. [공유 휴지통 계약](workspace-trash.md).

## 노트 AI 대화

노트 편집기 **AI 대화**(창 머리에 현재 노트 제목)는 집필실과 같은 제공자 연결·AI 설정·계정 프리셋·수정 적용·복구 지점을 사용한다. **아이디어 확장**, **브레인스토밍**, **생각 정리**, **문장 다듬기**, **자료 질문**으로 시작할 수 있다. API 키·모델을 연결해야 전송된다. [AI 연결·한도](ai.md).

현재 노트 포함 여부를 고르고 다른 개인 노트와 **이 노트에 연결한 작품**의 문서 중 참고 자료 최대 8개를 명시적으로 선택한다. 처음에는 참고 자료를 하나도 선택하지 않는다. 연결 작품의 본문이나 하위 노트 전체를 자동 전송하지 않는다. 현재 노트 최대 12,000자·자료 앞 1,800자·질문 2,000자·최근 완전한 대화 5회/24,000자, 집필실과 합계 하루 10회 제한을 공유한다.

대화는 노트별 20회, 계정 노트 중 대화 200개까지 저장한다. 성공 질문·답변을 한 번에 기록하고 실패 시 질문을 남긴다. 답변 후 노트가 바뀌면 수정 적용을 막는다. **대화를 노트로 보관**은 현재 노트의 하위 노트로 내용을 복사한다. **새 대화**는 복구 지점을 만든 뒤 해당 노트의 기록만 비운다. 실제 제공자 호출·비용·답변 품질 확인과 합성 응답 검증은 구분한다.

## 작품 연결과 가져오기

**작품 연결**에서 여러 작품을 선택할 수 있다. 연결해도 노트의 소속은 계정이고 원본은 하나다. 연결된 작품 칩으로 집필실을 열며, 집필실의 **참고 패널 → 연결 → 이 작품에 연결된 노트**에서 원본으로 돌아간다.

`…` → **작품으로 가져오기**에서 대상 작품과 원고·설정집·메모 종류를 고르면 새 비공개 문서가 열린다. 본문과 첨부를 복사하고 원본 노트는 남긴다. 첨부·문단·각주의 새 ID를 생성하며 사본 수정은 원본을 바꾸지 않는다. 대상 작품을 노트의 연결 목록에도 추가한다. 실제 공개는 집필실에서 판본을 만들 때 선택한 원고·공개 설명만 포함한다.

## 저장과 보존

`Workspace.notes`와 선택 필드 `Workspace.noteNavigation`에 저장하며 `author:<UUID>` 계정 분리, IndexedDB 직렬 저장 큐, Supabase 버전 검사·충돌·Realtime, 복구 이력과 전체 ZIP을 공유한다. `/studio#notes/<UUID>` 주소는 현재 노트를 여는 기기 화면 상태이고 권한은 기존 작가 인증을 따른다.

전체 ZIP에는 제목·리치 본문·태그·수집함/아이스박스·작품 관계·시각·폴더/노트 부모·형제 순서·노트별 aiMessages·원본 첨부와 이력 노트를 포함한다. 읽기 사본은 `text/notes/<UUID>.md`다. 이전 형식 1 백업에 notes 필드가 없으면 현재 노트와 원본 첨부를 유지하고 복원본에 없는 작품 연결만 제거한다. notes 배열이 있는 백업은 그 배열을 복원한다. 계층·AI 필드가 빠진 이전 백업은 공통 ID 노트의 현재 계층·AI 기록을 보존하며 새 ID 노트는 최상위로 보충한다. 명시된 noteNavigation·aiMessages는 빈 배열을 포함해 정확히 복원한다. MD/HTML/ENEX 교환 대화상자는 여전히 작품 문서 대상이다.

[서버 보호 마이그레이션](../supabase/migrations/20261004063340_independent_notes_guard.sql)은 notes 배열을 누락한 이전 클라이언트의 저장을 거절한다. 최신 앱은 이전 전송에도 notes 배열을 명시한다. 추가 [계층·AI 보호 SQL](../supabase/migrations/20261004074609_note_hierarchy_ai_guard.sql)은 기존 noteNavigation·같은 노트의 aiMessages 누락을 막는다. 오류 안내에 따라 구버전 탭의 미저장 글을 사본으로 보관한 뒤 새로고침한다.

모든 작품과 노트는 여전히 한 작업 공간 JSON이다. 다른 문서끼리도 충돌할 수 있고 서버 JSON 한도 20,000,000바이트를 함께 사용한다. 노트당 태그 20개(40자), 작품 연결 100개, 첨부 200개, 계정 노트 5,000개, 계정 첨부 2,000개, 이미지 10MiB 한도를 따른다. 외부 계정 동기화, 노트 간 링크·보드는 이번 범위에 없다. 노트가 AI 자료에 자동 포함되지 않는다.

## 검증

검증 환경과 실제 조작 결과는 [검증 기록](../VERIFICATION.md)과 [상태](status.md)를 따른다. 단위 테스트는 [personal-notes.test.ts](../tests/personal-notes.test.ts)와 [계층·AI 테스트](../tests/note-hierarchy-ai.test.ts), UI는 [personal-notes.tsx](../src/components/personal-notes.tsx), 모델·복사·검색은 [personal-notes.ts](../src/lib/personal-notes.ts)에 있다.

[메타 항목 강조 회귀 검사](../tests/browser/note-metadata-focus.mjs)는 실행 중인 로컬 앱과 별도로 설치된 `playwright-core`/Chromium이 필요하다. 아래 명령은 Playwright 모듈 경로·브라우저 실행 파일을 해당 환경에 맞게 지정해 실행한다. 기본 앱 주소는 `http://127.0.0.1:3210`이며 `KOSMOS_TEST_BASE_URL`로 바꿀 수 있다. 테스트 앱의 공개 Supabase 설정에 맞는 로그인 캐시 키는 `KOSMOS_TEST_AUTH_STORAGE_KEY`로 지정한다. 실제 계정 대신 격리된 합성 로그인·Supabase 응답을 사용하고 화면과 측정은 무시되는 `test-results/note-metadata-focus`에 저장한다. CI의 Node 테스트에 자동 포함되지는 않는다.

```sh
KOSMOS_PLAYWRIGHT_MODULE=/absolute/path/to/playwright-core \
KOSMOS_CHROMIUM_PATH=/absolute/path/to/chromium \
pnpm exec tsx tests/browser/note-metadata-focus.mjs
```

[빠른 메모·노트 정리 회귀 검사](../tests/browser/note-quick-capture.mjs)는 같은 설정으로 실행한다. 집필실 Alt+N 빠른 메모의 초점·Ctrl/Cmd+Enter 저장·화면 유지·Esc 원고 복귀, **노트에서 열기**, 노트 공간 Alt+N, 원고와 노트 본문의 계산된 첫 줄 들여쓰기, 필터 팝오버·보기 버튼, `…` 메뉴의 아이스박스 이동과 1280/360px 가로 넘침을 확인한다. 화면은 `test-results/note-quick-capture`에 저장한다.
