# 작품에 속하지 않는 개인 노트

기준: 2026-10-04. 집필실 사이드바의 **노트**에서 작품을 선택하지 않고 생각·관찰·자료를 적는다. 기존 작품의 메모와 별도의 계정 자료다.

## 작성과 찾기

- 집필실 상단 **새 노트**, 노트 공간의 **새 노트**, 또는 Ctrl/Cmd+Shift+N으로 빈 노트를 열고 바로 본문을 입력한다. 제목은 선택 사항이며 비어 있으면 첫 번째 본문 줄을 목록에 표시한다.
- 집필실과 같은 편집기를 사용한다. 글꼴·기기 표시 크기, 저장되는 문자·문단·표 서식, 각주, 실행 취소와 본문 검색을 쓴다. 독립 노트에서 작품별 설정 링크 도구는 비활성이다.
- 왼쪽 **전체 노트 검색**은 제목·본문·태그를 함께 찾으며 여러 검색어를 모두 포함하는 노트를 표시한다. Ctrl/Cmd+K로 검색을 연다. 태그와 연결 작품으로 함께 좁힐 수 있다.
- 새 노트는 **수집함**에 들어간다. 문서 머리의 **아이스박스에 넣기**로 보관하고 **수집함으로 꺼내기**로 다시 꺼낸다. 전체 노트에서는 둘 다 보인다. 목록은 최근 수정 순이다.
- **태그 추가**에서 선택적으로 분류한다. 태그 칩으로 제거한다. 제목·태그·작품 연결을 입력하기 전에 본문부터 쓸 수 있다.
- **첨부 추가**에서 PNG/JPEG/WebP 이미지를 보관하고 목록에서 내려받는다. 본문 안 이미지 삽입은 아니며 기존 집필실과 같은 별도 참고 첨부다.

## 작품 연결과 가져오기

**작품 연결**에서 여러 작품을 선택할 수 있다. 연결해도 노트의 소속은 계정이고 원본은 하나다. 연결된 작품 칩으로 집필실을 열며, 집필실의 **참고 패널 → 연결 → 이 작품에 연결된 노트**에서 원본으로 돌아간다.

**작품으로 가져오기**에서 대상 작품과 원고·설정집·메모 종류를 고르면 새 비공개 문서가 열린다. 본문과 첨부를 복사하고 원본 노트는 남긴다. 첨부·문단·각주의 새 ID를 생성하며 사본 수정은 원본을 바꾸지 않는다. 대상 작품을 노트의 연결 목록에도 추가한다. 실제 공개는 집필실에서 판본을 만들 때 선택한 원고·공개 설명만 포함한다.

## 저장과 보존

`Workspace.notes`에 저장하며 `author:<UUID>` 계정 분리, IndexedDB 직렬 저장 큐, Supabase 버전 검사·충돌·Realtime, 복구 이력과 전체 ZIP을 공유한다. `/studio#notes/<UUID>` 주소는 현재 노트를 여는 기기 화면 상태이고 권한은 기존 작가 인증을 따른다.

전체 ZIP에는 제목·리치 본문·태그·수집함/아이스박스·작품 관계·시각·원본 첨부와 이력 노트를 포함한다. 읽기 사본은 `text/notes/<UUID>.md`다. 이전 형식 1 백업에 notes 필드가 없으면 현재 노트와 원본 첨부를 유지하고 복원본에 없는 작품 연결만 제거한다. notes 배열이 있는 백업은 그 배열을 복원한다. MD/HTML/ENEX 교환 대화상자는 여전히 작품 문서 대상이다.

[서버 보호 마이그레이션](../supabase/migrations/20261004063340_independent_notes_guard.sql)은 notes 배열을 누락한 이전 클라이언트의 저장을 거절한다. 최신 앱은 이전 전송에도 notes 배열을 명시한다. 오류 안내에 따라 새로고침한 뒤 다시 저장한다.

모든 작품과 노트는 여전히 한 작업 공간 JSON이다. 다른 문서끼리도 충돌할 수 있고 서버 JSON 한도 20,000,000바이트를 함께 사용한다. 노트당 태그 20개(40자), 작품 연결 100개, 첨부 200개, 계정 노트 5,000개, 계정 첨부 2,000개, 이미지 10MiB 한도를 따른다. 삭제·휴지통, 외부 계정 동기화, 노트 간 링크·보드, 독립 노트의 AI 대화는 이번 범위에 없다. 노트가 AI 자료에 자동 포함되지 않는다.
