# Vertex AI · Gemini·Claude 대화

## 집필 작업 대화 (2026-11-09)

문서를 오가며 이어지는 **작업 대화**를 별도로 추가했다. 선택 작품/노트 공간 안에서 에이전트가 검색·읽기·생성·수정·정리하고, 검토 또는 맡겨 실행 방식으로 반영한다. Gemini 웹 조사와 세션 기억·변경 비교·되돌리기를 제공한다. 이 문서의 문서별 선택 자료·즉시 응답 계약은 기존 AI에 적용한다. 새 기능은 [별도 사용 계약](writing-agent.md)과 [서버 설정](setup-deployment.md#집필-작업-대화)을 따른다.


## 화면 문구 (2026-10-10)

집필실·노트의 AI 대화는 짧은 시작 버튼과 **질문 입력** 칸을 표시한다. 인사말·저장/동기화/백업 안내·긴 예시 요청은 상시 나열하지 않는다. 시작 버튼은 기존 요청을 질문 칸에 채우며 직접 전송하기 전에는 호출하지 않는다. **보낼 자료**의 현재 포함 여부·자료 수·전송 한도, 연결 오류·생성 상태·요청 한도는 유지한다. **새 대화** 확인은 현재 기록을 비운다는 결과를 한 문장으로 알린다. 모델 선택 상태는 설정에서 확인한다. 기록·프리셋·스킬의 저장과 전송 범위는 아래 계약과 같다.


Vertex AI를 공통 전송 경로로 사용하는 문서·개인 노트별 대화 화면을 구현했다. 운영 환경 변수 등록과 사용자 보고의 Claude 접근 승인을 확인했으며 실제 호출·한국어 SF 답변 품질·지연·사용료는 별도 검증 대상이다. 연결은 [서비스 연결 안내](service-connection.md)를 따른다.

## 원고 범위와 적용

질문을 직접 쓰거나 문장 퇴고·설정 점검·장면 구상·문서 요약·SF 개연성·자료 질문으로 시작한다. 보낼 자료에서 현재 문서 포함 여부와 같은 작품의 참고 문서나 개인 노트를 고른다. 처음에는 연결 설정과 시점 인물 자료를 선택한다. 질문·원고·참고 자료에 앱의 글자 수·개수 제한을 두지 않으며 선택한 자료는 전문을 전송한다. 다른 작품의 문서와 삭제되거나 없는 자료는 거절한다. 선택하지 않은 작품 전체나 외부 자료를 자동 조회하지 않는다.

UI는 기기 저장·클라우드 동기화를 시도하고 서버가 작가 권한·작업 공간 소유권·문서 updatedAt을 확인한다. 답변과 최대 5개의 수정 제안을 구조화 출력으로 받는다. 원고를 제외한 요청의 수정 제안은 서버에서 비운다. 작가가 제안을 선택하면 적용 전 복구 지점을 만든다. 답변 후 원고가 바뀌면 적용을 막는다.

선택 적용은 인용이 단일 텍스트 노드에서 정확히 한 번 나타날 때만 가능하다. 각주·설정 mark를 보존한다. 한 제안을 적용한 뒤 다른 제안은 새로 질문하거나 직접 비교해야 한다. AI 실패는 원고 저장을 멈추지 않는다. 전송 실패 시 질문을 유지한다. 답변을 기다리다 다른 문서를 열어도 결과는 원래 문서에 저장한다.

## 대화에서 @ 참고 자료

노트·집필실의 **AI 대화** 질문 칸에 `@`를 입력하면 제목·경로로 참고 자료를 찾는다. 위·아래 키와 Enter 또는 클릭으로 고르면 질문에 `@제목`을 넣고 **보낼 자료**의 선택 목록에도 추가한다. 같은 제목은 폴더·작품 경로로 구분하며 같은 자료는 중복 추가하지 않는다. Esc는 검색만 닫고 질문을 유지한다. 검색 목록이 열린 동안 Enter는 자료를 고르며, 결과가 없을 때는 전송하지 않는다. 다만 `@` 뒤 글에 공백이 있고 일치하는 자료가 없으면("@username 같은 표기"처럼 문장 속 `@`) 자료 검색으로 보지 않고 목록을 닫으므로 Enter로 바로 보낸다. Shift+Enter는 줄바꿈이다.

노트 대화에서는 다른 개인 노트와 연결 작품 문서를, 집필실 대화에서는 같은 작품 문서와 개인 노트를 고른다. 휴지통과 현재 문서는 검색에서 제외한다. 본문 편집기의 비공개 참조를 만들거나 다른 글로 이동하는 기능은 아니다. 검색·선택만으로 AI를 호출하지 않는다.

참고 자료의 체크박스와 같은 선택 상태를 사용한다. 체크박스 창을 닫으면 질문 입력으로 돌아가며, 이미 다른 곳으로 옮긴 초점은 유지한다. 질문에서 제목을 지우는 것만으로 첨부를 해제하지 않으며, **보낼 자료**의 자료 칩이나 체크박스로 제외한다. 전송할 때 서버 저장본의 선택 자료 전문을 보내고 답변에 출처 ID·제목을 저장한다. 검색어·선택 목록은 해당 대화 화면의 임시 상태이며 백업 계약·원고 내용은 바꾸지 않는다.

## 커서에서 선택한 글에 질문

집필실 원고·설정집·메모·분할 편집과 개인 노트에서 Alt+Enter 또는 `/AI`, 선택 글 우클릭 메뉴로 AI 질문을 연다. [집필실 조작](editor-tools.md#입력-명령과-ai-질문), [노트 조작](personal-notes.md#-입력-명령과-ai-질문). 이 창은 전체 문서 대신 선택 범위 또는 현재 문단을 보낸다. 서버는 작품/문서 또는 노트 ID·저장 버전·편집기 위치·원문을 대조해 불일치 시 AI 호출/한도 예약 전에 409로 거절한다. 문서 길이와 관계없이 선택한 범위만 전송한다. 각주 설명과 이미지 바이트는 포함하지 않는다.

기존 최근 대화·계정 프리셋·제공자 연결·요청 한도·문서/노트 대화 저장을 공유한다. 제공자 선택은 `kosmos:ai-provider:<namespace>` 기기 설정이며 백업·공개판에는 포함하지 않는다. 모델 목록·기본값과 빠른 선택의 저장 방식은 아래와 같다. 답변은 사용자가 편집·비교한 뒤 창을 열었던 범위에 교체하거나 커서에 삽입하며, 편집기 기록으로 한 번에 되돌린다. 본문이 바뀌거나 적용 전에 창을 닫으면 적용하지 않는다. 커서 답변은 오른쪽 대화에도 보이지만 그곳에는 인용 검색 기반의 자동 적용 제안을 저장하지 않는다.

## 내 스킬

자주 하는 요청을 **내 스킬**로 저장해 노트·집필실의 `/` 메뉴, 선택 글 우클릭, AI 질문 창에서 부른다. 관리 화면은 AI 설정의 **내 스킬** 구역이며 `/스킬 관리`로 연다. 이름 40자·선택 설명 120자는 유지하며 요청 길이와 스킬 개수의 앱 제한은 없다. 선택하면 질문 칸에 채워지고 보내기 전에는 호출하지 않는다.

스킬을 고르면 요청이 질문 칸에 채워진다. 수정하거나 그대로 보내며 메뉴를 고르는 것만으로 AI를 호출하지 않는다. 전송 범위는 다른 AI 질문과 같이 선택한 글, 선택이 없으면 현재 문단이다. 요청 안에서 그 글은 ‘보낸 글’이라고 부르면 된다. 앞뒤 문단을 자동으로 더하거나 요청 안에 원문을 끼워 넣는 자리 표시는 없다. 프리셋은 그때 적용 중인 프리셋을 쓰며 스킬마다 고정하지 않는다(서버가 활성 프리셋과 다른 요청을 오래된 탭으로 보고 거절하기 때문이다).

스킬은 `Workspace.aiPreferences.skills`에 저장되어 프리셋과 같이 기기·클라우드에 동기화되고 전체 ZIP·Drive ZIP·DB 수집에 포함된다. 공개 판본과 문서 교환에서는 제외한다. 다른 창에서 바뀐 스킬은 최신 내용을 불러온 뒤 저장한다. 삭제 전에 복구 지점을 만든다. 스킬 필드를 모르는 이전 버전의 열린 탭이 저장하면 스킬이 빠질 수 있으니 배포 후 열린 탭은 새로고침한다.

## 개인 노트에서 사용

노트 편집기의 **AI 대화**는 같은 제공자 연결·프리셋·요청 한도를 사용한다. 아이디어 확장·브레인스토밍·생각 정리·문장 다듬기·자료 질문으로 시작하며 현재 노트와 선택한 다른 노트 또는 연결 작품 자료만 전송한다. 참고 자료는 처음에 선택하지 않는다. 계층 부모·하위 노트를 자동으로 포함하지 않는다. 연결하지 않은 작품 ID와 대상 위조는 서버에서 거절한다.

`PersonalNote.aiMessages`에 노트별 대화를 보관한다. 대화 횟수·대화가 있는 노트 개수의 앱 제한은 없다. 저장 시 노트 본문의 updatedAt은 바꾸지 않으며 수정 적용은 같은 시점의 본문에서만 허용한다. **대화를 노트로 보관**은 하위 노트를 만들고 **새 대화**는 복구 지점 뒤 기록을 비운다. ZIP·이력에 포함하며 공개 판본에서 제외한다. [노트 사용법·복원](personal-notes.md).

## 대화 기록과 보관

작품의 선택 필드 `aiConversations`에 문서 ID와 대화 배열을 저장한다. 문서별 대화 횟수와 작품별 대화 개수를 제한하지 않는다. 다음 요청에는 저장된 질문·답변의 완전한 쌍을 순서대로 전달하며 최근 5회·24,000자에서 자르지 않는다. 질문·답변 순서 검증과 다른 창의 대화 변경 검사는 유지한다. 제공자 모델의 문맥 한도를 넘기면 오류로 돌려주며 기록을 자동 삭제하지 않는다.

질문과 성공 답변을 한 번에 저장한다. 질문·답변·수정안·제공자·모델·답변 당시 원고 시점·자료 제목/ID·프리셋 ID/제목/revision이 기기 저장, 클라우드 작업 데이터, 전체 ZIP, Drive 전체 ZIP, 암호화 DB 백업에 포함된다. 공개 판본에는 복사하지 않는다. 대화용 새 DB 테이블은 없다. 프리셋 보호용 003 마이그레이션을 적용한다. 기록은 서버의 작가 작업 공간 권한으로 보호한다.

**대화를 메모로 보관**은 질문·답변·수정안을 일반 메모로 복사한다. 메모는 기존 Markdown·HTML·ENEX 내보내기를 사용한다. **새 대화**는 확인 화면을 거쳐 현재 문서의 기록을 비우고 먼저 복구 지점을 만든다. 최근 기기 복구 지점은 기존 50개 보관 정책을 따른다.

## 집필실에서 연결·시스템 프롬프트 설정

**AI 대화 → AI 설정** 또는 사이드바 **설정 › AI**에서 Gemini·Claude를 고르고 **모델 목록**에 ID를 한 줄에 하나씩 넣는다. **기본 모델**을 정해 **모델 저장**을 누르면 문서·노트·커서·작업 대화의 **모델** 드롭다운에서 바로 고를 수 있다. 인증은 서버의 `orbiter-ai` 프로젝트가 담당한다. 브라우저에서 API 키를 받지 않는다. **기본 모델 사용**은 이 브라우저의 목록·기본값을 지우고 서버 목록으로 돌아간다. 모델 저장 자체는 AI를 호출하지 않으며 실제 접근 가능 여부는 요청 시 확인한다. 새 대화의 문서·연결 자료 포함 기본값은 [설정](settings.md)을 따른다.

모델 목록·기본 모델 ID를 계정·제공자에 묶인 AES-256-GCM HttpOnly 쿠키에 최대 30일 보관한다. 대화창의 빠른 선택은 계정별 기기 설정 `kosmos:ai-models:<namespace>`에 ID만 보관하고 같은 화면의 다른 AI 도구와 공유한다. 요청마다 선택 모델을 명시하며 실행 중인 에이전트의 모델은 시작 시 고정한다. 목록에서 지운 빠른 선택은 목록의 기본값으로 돌아간다. 모델 개수의 앱 제한은 없지만 암호화 쿠키 3,800자 경계를 넘으면 일부만 저장하지 않고 413으로 거절한다. 운영 쿠키는 `__Host-`·Secure·SameSite=Strict·Path=/를 사용한다. 만료·변조된 선택은 실행을 막고 다른 모델로 자동 전환하지 않는다. 선택은 다른 기기·도메인 및 ZIP/Drive/DB 백업으로 복사하지 않는다. 암호화에는 `AI_CREDENTIAL_SECRET` 또는 목적을 구분해 파생한 `SUPABASE_SERVICE_ROLE_KEY`를 사용한다. 예전 직접 API 키 쿠키는 사용하지 않으며 모델 저장·초기화 시 삭제한다.

**시스템 프롬프트·프리셋**은 계정 작업 공간에 저장하고 원고와 함께 기기·클라우드에 동기화한다. 창작 파트너·문장 퇴고·설정/시간선 점검·SF 가정/개연성·장면/구조 구상·독자 관점 검토 6종, 프리셋 이름은 80자이며 사용자 프리셋 개수·지침 길이의 앱 제한은 없다. 대화창의 **프리셋** 선택으로 다음 질문부터 바꾼다. 고른 프리셋은 [작업 대화](writing-agent.md#에이전트가-받는-지침과-작업-환경)의 성격으로도 쓰인다.

AI 설정에서 편집할 프리셋을 골라 **선택 적용**하거나 이름·지침을 작성해 **저장·적용**한다. 기본 프리셋 수정은 사용자 사본을 만든다. **사본으로 저장·적용**, **기본값으로 재설정**도 가능하다. 재설정은 사용자 프리셋을 보존한다. 빈 지침은 기본값으로 저장한다. 미저장 전환을 확인하며 다른 창의 수정이 있으면 최신 내용 또는 사본 저장을 선택한다. 삭제 전 복구 지점을 만들고 활성 프리셋 삭제 시 기본값으로 돌아간다. 이 동작들은 AI를 호출하지 않는다.

전체 ZIP·Drive ZIP·DB 수집에 포함하고 공개 판본·문서 MD/HTML/ENEX 교환에서 제외한다. 이전 백업에 필드가 없으면 현재 라이브러리를 유지한다. 예전 지침은 **이전 지침 불러오기** 후 명시적으로 저장한다. 서버 인증과 기기의 모델 선택은 별도다. 타이핑만 한 내용은 저장되지 않으므로 창을 닫기 전 저장·적용하고 클라우드 상태를 확인한다. [프롬프트 근거·평가](ai-prompts.md).

사용자가 수정하는 집필 지침과 별도로 자료 범위, JSON 응답 형식, 정확한 원문 인용, 자동 적용 금지 같은 서버 규칙을 유지한다. 참고 문서와 과거 대화에 들어 있는 지시를 새로운 시스템 지침으로 취급하지 않는다.

## 서버 연결

일반 대화·커서 AI·작업 대화는 모두 `@ai-sdk/google-vertex`로 호출한다. Gemini는 Google publisher, Claude는 Anthropic publisher를 사용하지만 인증·과금 프로젝트는 같은 `orbiter-ai`다. OpenAI·Anthropic·Gemini Developer API 키와 이전 별칭은 읽지 않는다. 과거 OpenAI 대화의 표시와 백업 호환성은 유지한다.

Vercel은 OIDC → GCP Workload Identity Federation → 서비스 계정의 단기 OAuth 토큰을 사용한다. 토큰은 서버의 실행 단계에서 만들며 브라우저·대화 기록·Workflow 모델 인자에 넣지 않는다. 로컬은 Application Default Credentials를 사용한다. `GOOGLE_VERTEX_PROJECT`와 `VERTEX_GEMINI_MODEL`·`VERTEX_CLAUDE_MODEL`, 인증 설정이 필요하다. 웹 조사는 같은 프로젝트의 `VERTEX_SEARCH_MODEL`(없으면 Gemini 기본 모델)을 사용한다. [설정 절차](vertex-ai.md).

두 모델 계열은 공유 지침과 최대 5개 수정 제안의 구조화 응답 계약을 사용한다. SDK는 Vertex Claude에서 JSON 도구 출력을 사용하며 서버가 결과 스키마를 검증한다. 요청은 4MiB, 출력 설정은 8,192토큰(Gemini는 생각 토큰 포함), 즉시 대화 타임아웃은 45초·함수는 60초다. 앱의 일일 횟수·질문 글자 수 제한은 없다. 프로젝트 할당량·모델 문맥·Vertex 요금은 적용된다. 모델·제공자를 자동 전환하지 않는다. 월 예산 강제 상한은 앱에 없다.

## API

POST `/api/ai/chat`: 작가 Bearer 인증 필요, JSON 본문은 스트림 기준 4MiB까지.

```json
{
  "workId":"작품 UUID","docId":"문서 UUID","version":"문서 updatedAt",
  "provider":"gemini","model":"선택한 Vertex 모델 ID","message":"질문","includeManuscript":true,
  "sourceIds":["같은 작품 자료 UUID"],
  "promptPresetId":"builtin:default 또는 사용자 UUID",
  "systemPrompt":"선택 프리셋의 집필 지침 · 길이 제한 없음",
  "history":[{"role":"user","content":"지난 질문"},{"role":"assistant","content":"지난 답변"}]
}
```

커서 요청은 작품 문서의 `documentRange` 또는 노트의 `noteRange`에 `{kind:"selection"|"paragraph",from,to,text}`를 추가한다. 각 필드는 해당 대상과 `includeManuscript:true`에서만 허용하고 다른 범위를 함께 보내면 거절한다. 위치는 실제 문서 스키마의 UTF-16/노드 위치이며 서버 저장본의 텍스트와 일치해야 한다. 빈 현재 문단은 허용하지만 빈 선택은 거절한다. 범위는 저장하지 않고 답변은 기존 대화 형식에 보관한다.

개인 노트 요청은 workId 대신 noteId를 보내며 docId도 같은 노트 UUID다. workId/noteId 중 하나만 허용한다. sourceIds는 다른 개인 노트 또는 연결 작품 문서 UUID다.

model은 생략하면 저장한 기본값을 사용하고, 있으면 경로 없는 Vertex 모델 ID를 검증해 이번 요청에 고정한다. 목록은 선택 편의 기능이며 실제 모델 접근은 GCP 권한과 활성화 상태를 따른다.

history는 user/assistant 순서의 완전한 쌍만 허용하며 system 역할을 받지 않는다. 서버에서 현재 원고·자료를 다시 읽고 권한·시점·선택 범위를 검사한다. 일일 횟수를 예약하거나 제한하지 않는다. 서버 활성 프리셋과 ID·지침을 검사하며 이전 ID 없는 요청은 호환한다. 성공 결과는 result(답변을 담은 review 문자열과 suggestions), provider, model, version, sources, promptPreset(id/title/revision)다. 응답은 no-store다.

GET `/api/ai/providers`: 허용 작가의 Bearer 인증 필요. 제공자 ID·표시명·configured·기본 모델·models 목록·source(server/null)·browserStored·browserInvalid와 서버의 storageAvailable을 반환한다. 인증 정보와 암호문은 반환하지 않으며 no-store다.

POST `/api/ai/settings`: 같은 Origin과 허용 작가의 Bearer 인증, application/json 필요. 본문은 `{"provider":"gemini","model":"기본 모델 ID","models":["기본 모델 ID","다른 모델 ID"]}`이고 스트림 기준 8KiB까지다. models는 생략할 수 있고 이전 모델 하나만 저장한 쿠키도 계속 읽는다. 목록을 보내면 중복·빈 목록·목록 밖 기본값을 거절한다. API 키 필드와 OpenAI 선택은 거절한다. 성공 본문은 `{"saved":true}`이고 모델 선택 쿠키를 설정하며 이전 직접 키 쿠키는 삭제한다.

DELETE `/api/ai/settings`: 같은 인증·Origin·JSON 조건에서 `{"provider":"gemini"}`로 모델 선택과 이전 직접 키 쿠키를 해제한다. 과거 OpenAI 쿠키의 삭제도 지원한다. 두 응답은 no-store다. 형식 오류 400, 인증 없음 401, 다른 Origin 403, 크기 초과 413, JSON 형식 아님 415, 암호화 설정 없음 503을 구분한다.

이전 POST `/api/review`도 호환을 위해 유지한다. 같은 인증, JSON 본문이며 Content-Length가 없어도 스트림 전체를 10,000바이트로 제한한다.

```json
{"workId":"작품 UUID","docId":"문서 UUID","version":"문서 updatedAt","goal":"style","provider":"gemini"}
```

goal은 style 또는 continuity, 새 요청의 provider는 anthropic / gemini이며 생략 시 gemini다. 과거 openai 값은 기록 호환에만 남고 실행은 거절한다. 성공 결과는 result(검토 의견·quote/replacement/reason 제안), provider, model, version, sources다.

| 응답 | 의미 |
|---|---|
| 400 | 요청 형식 오류 |
| 401 | 유효한 작가 로그인 없음 |
| 403·404 | 권한·작품·문서 조회 실패 |
| 409 | 문서 시점 또는 프리셋과 서버 저장본 불일치 |
| 413 | 요청 바이트 초과 |
| 502 | 제공자 오류·시간 초과·거부·불완전하거나 잘못된 결과 |
| 503 | 선택 제공자의 키·모델 미설정 |

외부 제공자 계약은 모의 HTTP 응답으로 테스트했다. 대화 백업 왕복·공개 판본 제외·다른 작품 자료 차단·시점/길이/역할 경계와 모델 선택 암호화·계정/제공자 구분·만료·변조·Origin·쿠키 속성·비밀값 미반환·Vertex 두 계열의 사용자 프롬프트를 테스트했다. 실제 프로젝트 권한으로 성공·거부·한도·비용을 시험한 결과가 아니다. 선택 문단 전송·작품 전체 자동 검색·스트리밍·장편 작업 큐는 후속 기능이다.
