# 개인 소설 집필·공개·설정집 통합 사이트 설계안

설계 버전: 0.5 / 2026-10-01 · 목표 설계

이 문서는 제품·화면·데이터·운영의 목표 설계다. 첫 로컬 구현과 실제 Supabase 초기 스키마 설치를 수행했으나 작가 클라우드 사용, Vercel 배포와 AI 연결은 완료하지 않았고 아래의 모든 기능을 구현한 상태는 아니다. 현재 동작은 [구현 상태](status.md), [아키텍처](architecture.md), [검증 기록](../VERIFICATION.md)을 기준으로 한다. 예시 사이트명 ‘궤도 서재’와 예시 작품명 ‘먼 별의 항구’는 교체 가능하다. 이 문서는 원래 요구사항을 보존하며 현재 구현의 경계는 별도로 기록한다.

## 1. 목표와 기본 가정

한 작가가 SF 중단편·장편을 집필하고, 준비된 판본을 공개하며, 작품별 설정집을 운영한다. 집필 단위는 작품의 서사 구조를 따른다. 연재 분량은 별도로 구성한다.

- 작가: 본인 1명. 관리자 계정만 로그인한다.
- 독자: 로그인 없이 공개 작품과 공개 설정집을 읽는다.
- 공개 방식: 첫 버전은 무료 열람과 수동 게시. 결제·회원·공동 편집은 추가하지 않는다.
- 집필 기기: 데스크톱·노트북 우선. 태블릿은 기본 편집, 휴대폰은 읽기·메모 우선.
- 원고 형식: 한글 문단 중심. 들여쓰기, 장면 구분, 인라인 강조, 주석, 설정 링크를 지원한다.
- 시각 방향: 공개 서재는 작품 이미지·타이포그래피를 중심으로 구성한다. 집필실은 Novela의 문서 탐색, Muvel의 분할·위젯, Pensiv의 플롯·연결 구조를 참고한 웹 편집기로 설계한다. 별도 레퍼런스 문서 design-references.md에 공식 화면과 근거를 모았다. 기존 인라인 시안은 v0.1의 축약안이며 이 개정안을 시각적으로 반영한 상태가 아니다.
- 기본 독서 방식: 세로 스크롤. 페이지 넘김 효과는 사용 후 필요성을 판단한다.

## 2. 제품의 핵심 규칙

1. 원고는 작품 → 부(선택) → 장(선택) → 장면으로 구성한다. 단편은 장 없이 장면만 사용할 수 있다.
2. 공개 회분은 선택한 장면의 판본을 순서대로 묶는다. 첫 버전에서 회분의 최소 편집 단위는 장면이다. 문장 중간을 공개 경계로 삼으려면 먼저 장면을 나눈다.
3. 집필실의 수정은 공개 사이트를 즉시 바꾸지 않는다. 작가가 공개 미리보기를 확인한 후 새 판본을 게시한다.
4. 작품별 원고·설정·검색·AI 문맥은 해당 작품에 한정한다. 여러 작품을 묶는 공통 세계관은 이후 기능이다.
5. 비공개 설정과 독자용 설명은 별도 문서로 보관하고 서로 연결한다. 공개 문서 생성 시 비공개 원문 전체를 복사하지 않는다.
6. AI는 원고와 설정을 근거로 제안한다. 자동으로 원고를 덮어쓰거나 설정을 확정하지 않는다.
7. 원고뿐 아니라 설정, 주석, 연결, 판본 이력도 백업한다. 서비스 밖에서 읽을 수 있는 형식을 제공한다.

## 3. 사이트 구조

### 공개 서재

| 주소 | 화면 | 주요 내용 |
|---|---|---|
| `/` | 서재 | 작가 소개, 대표 작품, 작품 목록, 짧은 공지 |
| `/works` | 전체 작품 | 단편·중편·장편, 연재 중·완결 필터 |
| `/works/{work}` | 작품 소개 | 표지, 소개, 완결 상태, 목차, 이어 읽기, 설정집 입구 |
| `/works/{work}/read/{release}` | 독서 | 공개 회분, 주석, 설정 미리보기, 이전·다음 회분 |
| `/works/{work}/wiki` | 설정집 목록 | 작품 내부 검색, 분류, 선택한 대표 문서 |
| `/works/{work}/wiki/{entry}` | 설정 문서 | 요약, 속성, 본문 목차, 관련 문서, 공개된 등장 위치 |
| `/about` | 작가 소개 | 작가 소개, 공개 연락처(선택) |

### 비공개 집필실

| 주소 | 화면 | 주요 내용 |
|---|---|---|
| `/studio` | 작품 선택 | 작업 중인 작품, 최근 편집 위치, 새 작품 |
| `/studio/works/{id}/write` | 집필 | 원고 트리, 장면 편집, 참고 설정, AI |
| `/studio/works/{id}/settings` | 설정 관리 | 확정·검토 중·폐기 설정, 공개용 문서 연결 |
| `/studio/works/{id}/publish` | 공개 준비 | 회분 구성, 공개 미리보기, 변경 비교, 게시 |
| `/studio/works/{id}/history` | 판본 이력 | 원고 복구, 공개판 이력, 판본 비교 |
| `/studio/works/{id}/export` | 내보내기 | 전체 백업, 원고용 Markdown/TXT |

공개 주소에는 읽기 쉬운 슬러그를 쓰되 내부 관계는 고유 ID로 저장한다. 제목이나 슬러그를 바꿔도 문서 관계는 유지한다. 이전 공개 주소에는 리디렉션을 남긴다.

## 4. 주요 화면

### 4.1 집필실

상단: 작품 전환 / 작업 공간 / 저장 상태 / 작업 배치 / 집중 모드 / 공개 미리보기. 공개 서재의 탐색 메뉴와 작가용 작업 메뉴를 각각의 화면 목적에 맞춰 구성한다.

가장 왼쪽: 작은 세로 메뉴로 문서, 검색, 구성, 설정, 자료, 공개 관리에 접근한다. 바로 옆 문서 탐색 패널에는 원고·설정·자료·메모를 폴더와 문서 트리로 표시한다. 문서 생성, 제목 변경, 접기, 고정, 순서 변경, 집필 상태 필터를 제공한다. 문서 행은 목록을 탐색하기에 충분한 밀도로 구성하고, 본문보다 작은 고딕체를 쓴다.

원고 트리는 부·장·장면 구조를 따른다. 장면 제목, 집필 상태(구상·초고·퇴고·완료), 분량을 표시한다. 키보드로도 문서를 열고 순서를 바꿀 수 있게 한다. 모든 문서의 상세 정보를 트리에 펼쳐두지 않고 선택한 문서의 속성에서 확인한다.

가운데 작업 영역: 여러 문서를 탭으로 유지한다. 탭 아래에 문서 경로, 도구 모음, 본문을 배치한다. 원고 + 설정, 원고 + 이전 장면, 원고 + 플롯의 2분할을 지원하고 경계에서 크기를 조절한다. 각 패널의 스크롤·커서 위치를 보존한다. 3·4분할은 후속 확장이 가능하도록 설계한다.

편집 도구: 실행 취소·다시 실행, 글꼴·크기, 강조, 정렬, 문단 들여쓰기·간격, 장면 구분, 주석, 설정 링크, 찾기 및 바꾸기. 설정 문서에는 제목·목록·표·인용·이미지도 제공한다. 선택한 문구에 문맥 메뉴를 열어 링크와 AI 검토를 실행한다. 도구 모음은 작은 아이콘과 명확한 레이블·설명을 사용하며, 단순한 세 개의 설명 버튼으로 대체하지 않는다.

오른쪽 보조 패널: 문서 속성 / 참고 자료 / 주석 / AI 검토를 필요에 따라 연다. 전체 설정 문서를 비교할 때는 편집 가능한 문서 분할을 사용하고, 짧은 정의·글자 수·메모는 접을 수 있는 작은 도구로 제공한다. 기본 화면에 모든 패널을 강제로 열어두지 않는다.

구성 화면: 장면의 요약·시점 인물·관련 원고·설정을 플롯 카드로 확인하고 순서를 조정한다. 원고 트리와 플롯 카드는 동일 장면을 참조한다. SF용 확장으로 작중 시간과 서술 순서를 비교하는 시간선을 설계한다. 첫 집필 도구 완성 범위에 기본 장면 보드와 관련 문서 연결을 포함한다.

작업 배치: 집필(원고 + 참고), 퇴고(원고 비교 + 검토), 구성(장면 보드 + 요약) 프리셋을 제공하고 사용자가 탭과 패널 배치를 저장한다. 그래프 캔버스와 다중 분할은 기본 집필실을 안정화한 뒤 확장한다. 장편은 장면별로 불러와 전체를 하나의 거대한 편집 문서로 처리하지 않는다.

장면 정보는 시점 인물, 장소, 작중 시각, 한 줄 요약만 첫 버전에 넣는다. 정보는 선택 입력이다. 상세한 지식 상태·복선·시간선은 이후에 확장한다.

집중 모드는 왼쪽·오른쪽 패널을 접는다. 전체 화면에서도 저장 상태와 집중 모드 종료는 접근 가능하다. 글자 수는 공백 포함/제외를 선택하게 하고, 페이지 수는 조판에 따라 달라지므로 확정 값으로 표시하지 않는다.

저장 상태: 이 기기에 저장됨 / 클라우드 동기화 중 / 클라우드 동기화됨 / 연결 끊김 / 충돌 확인 필요. 기기 저장과 서버 저장을 구분하고 서버 확인 이전에는 클라우드 저장 완료로 표시하지 않는다. 첫 버전부터 새로고침 복구용 기기 내 작업본과 전송 대기 기록을 남긴다. 기기 간 완전한 오프라인 동기화는 후속 기능이다.

### 4.2 독서 화면

상단은 작품명, 목차, 읽기 설정, 설정집으로 간결하게 구성한다. 본문에는 조회 수나 관리자 기능을 넣지 않는다.

- 본문 폭: 데스크톱에서 약 600~720px 범위. 독자가 글자 크기와 폭을 조절할 수 있게 한다.
- 글꼴: 명조를 기본 후보로 두고 고딕도 제공한다. 라이선스를 확인한 한글 폰트를 자체 호스팅한다.
- 문단: 첫 줄 들여쓰기와 문단 간격을 지원하고, 작품별 기본값을 작가가 지정한다.
- 장면 구분: 가운데 구분 기호 또는 간격. 에디터와 공개 화면에서 같은 의미로 렌더링한다.
- 읽기 위치: 해당 기기에서 저장한다. 이전 판본의 블록 ID가 유지되면 동일 위치로 복원하고, 삭제되었으면 인접 위치나 회분 처음으로 안내한다. 독자 계정이 없는 첫 버전에서는 기기 간 이어 읽기를 제공하지 않는다.
- 표시 설정: 글자 크기, 줄 간격, 본문 폭, 명조/고딕, 밝게/어둡게, 설정 링크 표시.
- 탐색: 이전·다음 회분과 목차. 각주나 위키를 열었다 돌아와도 원래 위치를 유지한다.

주석 번호는 PC에서 호버·키보드 포커스 시 미리보기를 열고, 클릭하면 하단 각주로 이동한다. 모바일에서는 탭으로 짧은 패널을 열고 ‘각주로 이동’을 제공한다. 각주에는 ‘본문으로 돌아가기’ 링크를 둔다. 단순 호버만으로 필요한 정보가 제공되는 설계는 피한다.

설정 링크는 작가가 선택한 단어에 연결한다. 짧은 정의를 먼저 보여주고 ‘설정집 열기’를 제공한다. PC의 클릭 대상은 정상 URL을 가진 링크로 만들고, 모바일 첫 탭은 미리보기와 명시적인 문서 이동을 제공한다. 자동 단어 인식은 연결 후보 제안에만 사용한다.

주석과 문서 링크는 모두 URL로 직접 접근할 수 있다. 링크가 깨지면 원고는 읽을 수 있지만 공개 준비 화면에 오류를 표시한다.

### 4.3 작품별 설정집

목록: 인물 / 장소 / 기술 / 세력 / 역사·사건 / 기타. 분류를 강제하지 않고 문서에 여러 분류를 지정할 수 있게 한다.

문서: 제목, 한 줄 정의, 별칭, 간단한 속성 표, 목차, 본문, 관련 문서, 본문에서의 등장 위치. 속성은 분류별 초기 양식만 제공하고 자유롭게 바꿀 수 있다.

기술 문서 예: ‘관성 항해’ / 원리 / 가능한 일 / 불가능한 일 / 비용·부작용 / 사용하는 세력 / 작품 내 최초 등장.

작가용 문서에는 근거 원문, 검토 메모, 확정 상태, 리서치 출처를 추가한다. 독자용 문서는 별도로 편집하고 공개한다. 비공개 원고를 참조하는 백링크와 장면 제목은 공개 문서에 노출하지 않는다.

설정집 검색은 현재 작품을 기본 범위로 한다. 문서 화면과 주소에 작품명을 유지해 같은 이름의 인물·기술을 혼동하지 않게 한다. 게시판 대신 문서를 지식의 기본 단위로 쓰며, 작가 후기·변경 기록은 별도 문서 분류로 처리한다.

### 4.4 공개 준비

작가가 공개 회분을 만들고, 장면을 선택·정렬한다. 제목·소개·회분 순서를 지정하고 독서 미리보기를 연다.

첫 게시 전 확인 항목: 포함한 장면, 해결되지 않은 설정 링크, 비공개 문서 연결, 주석 대상, 이전·다음 회분, 공개 설정집 판본. 검토가 필요한 항목을 해당 위치로 연결한다.

비공개 문서로 연결되는 링크는 공개를 막는 오류다. 작가는 공개용 문서를 작성해 연결하거나, 해당 링크를 공개본에서 제거한다. 단순히 비공개 문서 URL을 감추는 것으로 처리하지 않는다.

기존 회분 수정 시 이전 공개판과 변경 내용을 비교한다. ‘새 판본 게시’는 원고·주석·필요한 공개 설정을 하나의 게시 단위로 확정한다. 성공 전까지 기존 공개판을 유지한다.

회분을 비공개로 전환하면 목록과 직접 주소에서도 일반 독자가 접근할 수 없게 한다. 공개판 이력은 작가에게 보관한다. 이미 내려받은 사본까지 회수되는 기능으로 설명하지 않는다.

## 5. 원고·주석·설정 연결 방식

원고 문단에는 고유 블록 ID를 부여하고 주석·설정 링크를 문서 구조 안의 요소로 저장한다. ‘몇 번째 글자’만을 별도 저장해 문장이 수정될 때 엉뚱한 위치로 이동하는 구조는 피한다.

- 주석: 원고 안 참조 ID ↔ 해당 판본의 주석 본문. 번호는 공개 회분 안의 등장 순서로 계산한다.
- 설정 링크: 선택한 표현 ↔ 작품 내 공개 설정 항목 ID. 별칭을 표시해도 연결 대상은 고정된다.
- 공개 회분: 장면의 특정 판본 ID를 참조한다. 같은 장면의 다음 수정이 기존 회분을 변경하지 않는다.
- 문단 분할: 새 블록 ID와 이전 ID의 대응을 남긴다. 문단 삭제는 독서 위치 복원에만 대체 위치를 사용하며 존재하지 않는 주석을 다른 문장에 자동 부착하지 않는다.
- 문서 삭제: 공개판에서 참조 중이면 경고하고, 공개 링크의 해소·대체 없이 완전 삭제할 수 없게 한다.
- 같은 장면 재사용: 첫 버전에서는 같은 작품의 일반 연재 목차에 중복 포함하지 못하게 한다. 별도 개정판·선집은 이후 ‘판’ 개념으로 확장한다.

SceneVersion의 note_payload에는 해당 판본의 주석 본문을 저장한다. 주석 내용을 나중에 수정해도 이전 공개판의 각주가 바뀌지 않는다. 처음에는 문서 속 링크를 기준으로 파생 색인을 만들고, 독립적인 링크 편집 화면을 추가하지 않는다.

Publication의 manifest는 선택한 장면 판본과 순서, 공개 시 사용할 설정 미리보기 판본, 주석 렌더링 정보를 담는다. 독서 중 짧은 설정 정의는 해당 공개판 기준이다. 전체 설정 문서는 현재 공개 설정집으로 이동하며, 공개판 당시의 요약과 다를 수 있음을 문서의 수정일로 알린다. 전체 설정집의 시대별 판본을 독자가 전환하는 기능은 후속 범위다.

부·장 제목도 독서 목차에 포함된다면 게시 시 복사해 고정한다. 비공개 구조 변경이 공개 목차를 즉시 바꾸지 않게 한다.

## 7. 접근 권한과 공개 처리

- 관리자만 비공개 객체와 이력에 접근한다. 원고·설정·AI 호출은 owner_id와 work_id를 서버에서 확인한다.
- 일반 독자는 현재 공개된 회분과 공개 설정 판본만 조회한다. 과거 공개판 API를 임의 ID로 호출해서 접근할 수 없게 한다.
- 공개 페이지 데이터는 공개용 조회 경로로 구성한다. 비공개 초고·설정은 HTML, 브라우저 전송 데이터, 검색 색인에 포함하지 않는다.
- 공개 링크, 백링크, 검색 결과, 첨부 자료에도 같은 권한을 적용한다. 첨부 파일은 공개용·비공개용 접근 정책을 구분한다.
- 게시 처리에서는 판본을 저장하고 검증한 뒤 active_publication_id를 한 번에 전환한다. 실패 시 기존 판본을 유지한다.
- 수정·비공개 전환 시 공개 캐시와 검색 색인을 갱신한다. 캐시된 비공개 화면을 일반 독자에게 공유하지 않는다.
- 스포일러 접기는 공개 정보의 읽기 편의 기능이다. 비공개 설정에 대한 접근 제한과 동일한 기능으로 취급하지 않는다.

## 8. AI 기능 설계

### 첫 AI 버전

**설정 찾기**: 작품 내 확정 설정과 원고를 검색하고 답변에 문서명·장면·근거 문장을 연결한다. 근거가 없으면 ‘설정된 내용은 찾지 못했습니다’라고 답한다. 폐기 설정은 기본 범위에서 제외한다.

**선택 문단 검토**: 사용자가 선택한 문단 또는 현재 장면을 대상으로 반복, 모호한 지시어, 시점 흔들림, 문장 연결을 검토한다. ‘표현 유지 / 가볍게 다듬기 / 적극적으로 다듬기’를 선택한다. 원문·제안·이유를 보여주고 항목별 적용한다.

### 후속 AI 버전

- 정합성 검토: 기술의 한계, 장소·시간, 인물의 지식, 고유명사 표기 차이를 근거 두 곳과 함께 제시한다. 누락 가능성이 있는 보조 검토이며 작품 전체의 무모순을 보증하지 않는다.
- 구성 검토: 장면 요약을 바탕으로 정보 공개 순서, 미회수 복선 후보, 장면 목적을 검토한다.
- 설정 문서 초안: 선택한 원고에서 설정 후보를 추출해 ‘검토 중’ 상태로 제안한다. 확정과 공개는 작가가 수행한다.
- 과학 리서치: 외부 자료 검색을 명시적으로 실행한다. 현실 자료의 출처·발행 시점과 작품의 가상 규칙을 구분한다.

### 호출과 결과 규칙

호출 전에 현재 작품, 대상 원고, 포함할 설정의 범위를 표시한다. 검색은 work_id로 먼저 제한한 뒤 관련 자료를 선택한다. 장편 전체를 매번 전송하지 않는다. 필요한 경우 장면 요약과 관련 원문을 함께 사용하며, 요약은 설정의 근거 원문을 대체하지 않는다.

AI 결과는 검토한 원고 판본에 연결한다. 원고가 바뀌면 ‘이전 원고 기준’이라고 표시한다. 수정 적용 시 판본이 달라졌다면 다시 비교하고 충돌을 확인한다. 취소·실패·지출 한도 도달은 원고 저장에 영향을 주지 않는다.

AI 제공자는 서버에서 호출하고 키를 브라우저에 보내지 않는다. 제공자·전송 범위·보관 설정을 실제 계약과 구현에 맞게 안내하며, 정책 확인 없이 ‘학습에 사용되지 않는다’고 단정하지 않는다. 작품별 AI 활성화와 사용 한도를 제공한다.

## 9. 스포일러 정책

첫 버전: 작가가 공개용 문서의 내용을 직접 정하고, 문서 또는 섹션에 ‘스포일러 포함’ 표시와 펼치기를 넣는다. 미공개 설정은 공개 데이터에 포함하지 않는다.

후속 버전: 독자가 ‘읽은 회분’을 직접 선택해 설정집 섹션을 가린다. 스크롤 도달을 실제 읽음의 확정값으로 사용하지 않는다. 검색 결과·짧은 정의·관련 문서 제목에도 같은 표시 정책을 적용한다.

정체 자체가 스포일러인 경우 공개 문서 제목과 요약도 작가가 별도로 작성한다. 문서 본문만 접고 제목으로 비밀이 드러나는 구성을 피한다.

## 10. 운영과 내보내기

- 자동 저장과 판본 이력: 작업본을 자주 저장하고, 의미 있는 시점(장면 전환, 명시적 저장, AI 적용, 게시)에 복구 가능한 판본을 만든다. 저장 주기·이력 보존 기간은 사용량을 확인해 설정한다.
- 복구: 이전 판본을 복구할 때 현재 작업본을 보존하고 새 판본으로 만든다. 과거 공개판을 덮어쓰지 않는다.
- 백업: 서버 백업과 별도로 전체 작품을 ZIP(JSON + Markdown/TXT + 첨부 + 관계 manifest)으로 내려받는다. 주석과 설정 연결을 manifest에 보존한다.
- 가져오기: 첫 버전은 TXT/Markdown 또는 붙여넣기. 가져온 결과를 미리보기에서 확인하고 장·장면을 구분한다.
- 후속 내보내기: DOCX는 제출용 원고, EPUB은 독서용으로 구현한다. 주석 이동·설정 링크의 변환 규칙을 별도로 검증한다. HWP 원본 편집은 첫 범위에 포함하지 않는다.
- 읽기 설정과 읽기 위치: 독자의 기기 안에 보관한다. 첫 버전에서는 회원 정보·읽기 행동 분석을 수집하지 않는다.
- 운영 비용: 도메인, 서버·데이터베이스, 첨부 저장, AI 호출로 구분한다. 방문량과 AI 범위가 정해지기 전에는 고정 비용을 약속하지 않는다.

## 11. 권장 기술 구성과 경계

웹 UI와 서버: Next.js + React + TypeScript. 편집기: Tiptap/ProseMirror 기반 구조화 문서. UI는 Tailwind CSS와 필요한 구성 요소로 별도 설계한다. 현재 구현은 Radix 기반 자체 UI이며 shadcn/ui 템플릿을 사용하지 않았다. 호스팅은 Vercel, 데이터베이스·작가 인증·첨부·변경 알림은 Supabase(PostgreSQL/Auth/Storage/Realtime)를 기준으로 한다. 기기 내 저장은 IndexedDB + Dexie를 사용하고 서버 동기화는 별도로 구현한다. 목표 기술·비용은 [기술 제안](technical-proposal.md), 실제 구현은 [아키텍처](architecture.md)에 기록했다. 현재 로컬 구현이 있으며 실제 서비스 계정 연결과 외부 배포는 남아 있다.

문서 JSON을 원본으로 보관하고 독서용 HTML을 생성한다. 주석·설정 링크용 노드를 확장한다. HTML 출력은 허용된 태그와 속성만 사용한다. UI 화면을 먼저 만든 뒤 저장·권한을 나중에 덧붙이는 방식 대신 작은 작품으로 편집→저장→복구→게시→독서 흐름을 먼저 완성한다.

한국어 검색은 제목·별칭·본문의 문자열 검색으로 시작한다. 한국어 형태소 검색, 의미 검색, 벡터 색인은 실제 문서 수와 검색 품질을 확인한 뒤 추가한다. 전문 검색 기능이 한국어 형태소를 자동으로 잘 처리한다고 가정하지 않는다.

첫 버전은 클라우드 작업본 + 기기 내 복구본이다. 기기 내 전송 대기 기록을 유지하고 재접속 때 서버 버전을 비교한다. 서버 저장은 기준 버전 비교와 중복 요청 방지를 포함하며, 오래된 탭이나 다른 기기의 원고가 새 작업을 조용히 덮어쓰지 못하게 한다. 충돌하면 양쪽 원고를 보존하고 비교한다. Realtime은 변경 알림이며 자동 병합 도구가 아니다. 사이트를 오프라인으로 다시 여는 PWA, 실시간 공동 편집·CRDT·완전한 오프라인 병합은 후속 범위다.

| 사용 후 확장 | 시간선, 복선, 장편 정합성, DOCX/EPUB, 스포일러 단계 | 실제 집필에서 반복되는 불편을 해결함 |

첫 작동 버전의 검증 시나리오:

1. 한글 조합 중 저장·패널 전환으로 글자나 커서가 손상되지 않는다.
2. 브라우저 새로고침과 저장 실패 후 기기 내 임시본으로 작업을 복원할 수 있다.
3. 여러 탭의 오래된 원고가 새 작업을 조용히 덮어쓰지 않는다.
4. 장면 이동·주석 추가·설정 문서 이름 변경 후 연결이 유지된다.
5. 공개 후 원고·각주·설정을 수정해도 선택한 공개판은 그대로 남는다.
6. 일반 독자의 직접 URL·검색·백링크·첨부 요청으로 비공개 자료가 조회되지 않는다.
7. 게시 실패 시 원고와 설정의 판본이 섞이지 않는다.
8. 360px 모바일에서 주석·설정 미리보기·본문 복귀를 탭으로 사용할 수 있다.
9. 전체 백업에서 원고·설정·주석·관계를 복원할 수 있다.
10. 긴 작품도 장면 단위로 편집하며, 공개 페이지는 AI 완료를 기다리지 않고 읽을 수 있다.

## 13. 첫 버전에 넣지 않는 기능

독자 회원가입, 유료 결제, 댓글·커뮤니티, 공동 집필, 팬 위키 수정, 자동 연재, 페이지 넘김 애니메이션, 그래프 캔버스, 원고 자동 생성 에이전트, 완전한 오프라인 동기화, 여러 작품의 공통 세계관.

이는 영구 제외가 아니라 첫 출시의 경계다. 댓글이나 공개 참여가 실제로 필요해지면 권한·운영 방식과 함께 별도 설계한다.

## 14. 설계 후 결정할 항목

작가명·사이트명, 시각 방향, 공개할 첫 작품과 분량, 기존 원고의 형식, 초기 AI 제공자와 월 사용 한도, 운영 플랜과 도메인. 배포 기술은 Vercel + Supabase를 권장안으로 두었다. 이 항목이 정해지기 전에도 현재 설계의 화면·저장·공개 구조를 구체화할 수 있다.
