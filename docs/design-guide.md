# 디자인 가이드

기준일: 2026-10-04. 새 화면이나 기능을 추가할 때 기존 화면과 같은 색·글꼴·간격·문구를 쓰기 위한 규칙이다. 화면 시안은 작가 계정의 [디자인 캔버스](https://claude.ai/artifact/8JQvgoZDiTun4ZQ4Cp8FEW)(비공개)에, 여섯 테마의 토큰과 컴포넌트 미리보기는 [디자인 시스템](https://claude.ai/artifact/XVVsdiqKsa5D99pgd6gc1P)(비공개, main `a7ee675` 기준)에 있고, 참고 서비스 연구는 [디자인 레퍼런스](design-references.md)에 있다. 두 아티팩트는 레포 밖에 있어 다른 도구에서는 열리지 않을 수 있으며, 값이 다르면 이 문서와 CSS가 기준이다.

## 0. 새 화면을 만들기 전에 (필수)

새 기능은 **새 모양을 만들지 않고 아래 기존 부품을 조립한다.** 새 CSS는 배치(위치·크기)만 쓰고 색·모서리·글자 모양은 기존 클래스와 토큰에서 가져온다. 여기서 벗어나야 하면 먼저 이 문서에 이유와 새 패턴을 적는다. 2026-10-03 문서 그래프가 이 규칙 없이 만들어져 다른 앱처럼 보였고 다시 만들었다.

| 필요한 것 | 쓰는 부품 | 예시 |
|---|---|---|
| 탭 전체를 쓰는 화면의 위쪽 | `board-bar` 한 줄: 왼쪽 `segmented` 보기 전환·검색칸, 오른쪽 개수 `span`과 `.button` | 플롯보드, 문서 그래프 |
| 버튼 | `.button`, 주요 동작은 화면당 하나 `.button.primary`, 되돌릴 수 없는 삭제 확인은 `.button.danger`(`--danger` 글자·테두리, 호버 `--danger-soft`), 아이콘만 있으면 `IconButton` | 휴지통 영구 삭제 |
| 문서·설정을 짧게 표시 | `.chip`(`soft`·`ghost`) 또는 아이콘 + 제목 칩 | 문서 머리 칩, 플롯 카드, 그래프 노드 |
| 문서 종류·설정 분류 | Lucide 아이콘: 원고 FileText, 메모 StickyNote, 설정은 `WikiIcon`(인물 User·기술 Orbit·장소 MapPin…) | 트리, 그래프, 연결 목록 |
| 원고 상태 | `.status-dot` + `statuses` 이름 | 트리, 플롯 카드, 그래프 |
| 오른쪽 정보 영역 | 참고 패널 규격: 폭 300px, `--side` 바탕, 안쪽 20px 18px, 소제목 12px 600 `--muted` | 참고 패널, 그래프 정보 |
| 카드 묶음 | `board-column` + `plot-card` | 플롯보드 |
| 버튼 옆 작은 설정·필터·입력 | `Popover`, 행 동작은 `.menu`(8절 **떠 있는 창**) | 트리 메뉴, 문서 통계, 그래프 필터 |
| 화면을 막아야 하는 확인·큰 작업 | `Modal` | 충돌, 백업 |
| 안내·제한 알림 | `--soft` 바탕 한 줄 또는 `success`·`danger` 문구 | |

**하지 말 것**

- 탭 이름과 같은 제목 줄을 화면 안에 다시 쓰지 않는다. 탭 아래 고정 줄은 한 줄이다(주변 연결처럼 보기에 딸린 설정만 예외로 한 줄 더).
- 이미 아이콘이 있는 뜻을 다른 기호로 다시 표시하지 않는다. 예: 원고·메모·설정을 트리에서는 아이콘으로, 그래프에서는 네모·마름모·원으로 보여 주지 않는다. 한 뜻에 한 아이콘이다. 기존 아이콘이 없는 새 뜻에는 Lucide 아이콘을 새로 골라 쓰고 위 표에 더한다.
- 글자는 UI 13px, 보조 12px, 최소 11px. 굵기는 400·500·600만 쓴다. 확대·축소 화면에서도 UI 글자는 크기가 변하지 않게 한다.
- 버튼·입력칸·목록 항목에 새 테두리·바탕·모서리 규칙을 만들지 않는다.
- 아이콘과 입력칸을 한 줄로 묶는 부품(`sidebar-search`)은 `<label>`로 감싸지 않는다. 전역 `label`이 세로 배치(`flex-direction:column`)여서 아이콘이 입력칸 위로 올라간다. `div`로 감싸고 입력칸에 `aria-label`을 단다.
- 모양 토큰(`--ctl-r`·`--r-in`·`--panel-r`·`--led-r`·`--cut*`)은 사이버에만 정의되어 있다. **항상 기본값을 함께 쓴다**: `var(--ctl-r,6px)`, `var(--r-in,8px)`. 기본값이 없으면 보라·카세트에서 모서리가 사라진다.
- 색 계열 이름으로 분기하지 않는다. 카세트의 Mono 숫자·키 모양처럼 꼭 필요한 차이만 `[data-palette=…]` 규칙으로 더한다(4절).
- hex 값, 그라데이션, 새 그림자를 쓰지 않는다.

**끝내기 전에** 같은 탭 화면(플롯보드 등)과 나란히 여섯 조합 × 1280px·360px 화면을 찍어 위 표와 다른 곳이 없는지 본다. 그다음 11절 체크리스트를 확인한다.

## 2. 원칙

1. **바탕은 무채색, 색은 적게.** 바탕과 본문은 보라 기운이 아주 살짝 도는 회색·검정(카세트는 베이지·콘솔 검정)이다. 강조색은 브랜드·버튼·링크에만 쓴다. 그라데이션과 넓은 강조색 면은 쓰지 않는다.
2. **두 보라의 역할을 나눈다.** Ultra Violet(Pantone 18-3838, #5F4B8B)은 브랜드와 주요 동작, Very Peri(Pantone 17-3938, #6667AB)는 연결이다. 섞어 쓰면 탁해 보인다.
   - Ultra Violet `--pub-brand`: ◌ 표시, "서재 둘러보기"·"작품 읽기" 버튼, 표지, 설정 분류명.
   - Very Peri `--pub-link`: 설정 링크, 각주 번호, 읽기 진행 막대, 텍스트 링크.
3. **서재는 책, 집필실은 도구.** 공개 페이지는 명조 제목·넓은 여백·가는 구분선으로 책처럼, 집필실은 작은 고딕·촘촘한 배치로 작업 도구처럼 만든다. 색 규칙은 같고 레이아웃과 글꼴로 구분한다.
4. **꾸밈말보다 사실.** 슬로건·영문 장식 제목 대신 실제 데이터(편수, 날짜, 개수)를 보여준다. [7절](#7-문구)을 따른다.
5. **여섯 조합에서 모두 확인한다.** 새 화면은 보라·카세트·사이버 × 라이트·다크 여섯 조합에서 각각 보고, 본문 대비 4.5:1 이상을 지킨다.

## 4. 테마 (색 계열 × 밝기)

- 테마는 `<html>`의 두 속성으로 정한다. 밝기 `data-theme="light|dark"`와 색 계열 `data-palette="violet|cassette|cyber"`이다. 둘은 따로 고르며 여섯 조합이 모두 있다. 색 계열 목록은 `src/lib/theme.ts`의 `PALETTES`(이름은 `theme-toggle.tsx`의 `paletteOptions`) 하나에서 온다.
- `src/lib/theme.ts`의 `themeScript`가 `<head>`에서 첫 그리기 전에 실행된다. 밝기는 저장된 선택(`localStorage`의 `orbis-theme`)이 있으면 그것을, 없으면 기기 설정을 쓴다. 색 계열은 저장된 선택(`orbis-palette`)이 `cassette`일 때만 카세트, 나머지는 보라다.
- CSS는 `:root`(보라 라이트) → `[data-theme=dark]`(보라 다크) → `[data-palette=cassette]`(카세트 라이트) → `[data-palette=cassette][data-theme=dark]`(카세트 다크) 순서로 덮어쓴다. 마지막 블록은 선택자가 더 구체적이라 순서와 관계없이 이긴다.
- 공개 페이지 헤더마다 `ThemeControls`를 둔다. 왼쪽은 색 계열 고르기(보라 원 두 개 / 카세트 아이콘 / 사이버 Cpu 아이콘, `aria-pressed`), 오른쪽은 달/해 밝기 버튼이다. 다른 조작에서 바꿀 때는 `useSiteTheme()`·`useSitePalette()`를 쓴다. 독서 화면의 "읽기 설정 › 배경"과 "읽기 설정 › 테마"도 같은 값을 바꾼다.
- 이전 독서 설정(`orbit-reader-prefs`의 `theme: 'night'`)은 사이트 밝기가 저장되지 않은 경우에 한 번만 다크로 옮긴다.
- 집필실도 두 속성을 모두 읽는다. 사이드바 아래에 같은 `ThemeControls`가 있어 공개 페이지와 같은 `orbis-palette`·`orbis-theme` 값을 바꾼다. 집필실의 기본 토큰도 같은 순서(`:root` → `[data-theme=dark]` → `[data-palette=<계열>]` → `[data-palette=<계열>][data-theme=dark]`)로 덮어쓴다.

**새 공개 페이지를 만들 때**

1. 가장 바깥 요소에 `public-site` 클래스를 붙인다. 바탕·글자색·글꼴과 `<html>` 바탕(넘침 스크롤 영역)이 함께 적용된다.
2. 헤더에 `ThemeControls`를 넣는다. 기존 페이지는 `PublicHeader`(`public-site.tsx`) 또는 CSS 모듈 헤더(`page.tsx`·`privacy/page.tsx`)를 쓴다.
3. 버튼이나 단어에 딸린 작은 설정·설명은 `primitives.tsx`의 `Popover`, 화면 전체를 막아야 하는 확인·큰 작업은 `Modal`을 쓴다(8절 **떠 있는 창**). 공개 페이지가 열려 있으면 `html:has(.public-site) .popover`·`.modal` 규칙으로 테마 색을 따른다.
4. 색 계열마다 모양이 달라야 하면 3절의 모양 토큰을 쓰고, 그래도 부족할 때만 `[data-palette=cassette] .클래스` 규칙을 `globals.css`의 카세트 줄에 추가한다. CSS 모듈에서는 `:global([data-palette=cassette]) .클래스`로 쓴다.

**색 계열을 하나 더 추가할 때**

1. `globals.css`에 `[data-palette=<이름>]`(라이트)과 `[data-palette=<이름>][data-theme=dark]`(다크) 블록을 만들고 `--pub-*` 전체 값과 모양 토큰을 정의한다. 일부만 정의하면 보라 값이 섞인다.
2. `SitePalette` 타입, `preferredPalette`, `themeScript`의 허용 값에 이름을 추가하고 `tests/theme.test.ts`를 갱신한다.
3. `ThemeControls`에 고르기 버튼을, 독서 설정의 "테마" 목록에 선택지를 추가한다.
4. 네 화면(서재·독서·설정집·홈)을 라이트·다크와 360px 폭에서 확인하고 이 문서, [사용 안내](user-guide.md), [변경 기록](../CHANGELOG.md)을 고친다.

## 5. 글꼴과 글자 크기

| 변수 | 글꼴 순서 | 쓰는 곳 |
|---|---|---|
| `--pub-serif` | Gowun Batang → Batang → Noto Serif KR → serif | 사이트 이름, 페이지·작품·장면 제목, 첫 문장 발췌, 독서 본문(명조 선택 시) |
| `--pub-sans` | IBM Plex Sans KR → Apple SD Gothic Neo → Malgun Gothic → sans-serif | 메뉴·버튼·설명·날짜·각주·설정집 설명, 카세트의 제목 |
| `--pub-mono` | IBM Plex Mono → IBM Plex Sans KR → ui-monospace | 카세트의 날짜·개수·각주 번호·분류 글자. 한글은 IBM Plex Sans KR로 넘어간다 |
| `--pub-tech` | Michroma → IBM Plex Sans KR (사이버에서는 Chakra Petch) | 카세트·사이버의 사이트 이름, 홈 제목, 표지의 ORBIS TERTIUS. 사이버는 숫자·분류 글자에도 쓴다 |

사이트 웹폰트는 `src/app/layout.tsx`에서 Google Fonts 한 줄로 불러온다(Gowun Batang, Chakra Petch, IBM Plex Mono, IBM Plex Sans KR, Michroma). 제목은 `--pub-serif`를 직접 쓰지 않고 `--pub-title`을 쓴다(3절 모양 토큰).

작가가 선택하는 원고 글꼴은 별도다. 명조·고딕·코딩·손글씨·기기 글꼴 등 16가지를 제공한다([목록과 크기 범위](editor-tools.md#글꼴크기)). 크기는 10~72px에서 0.5px 단위로 직접 입력한다. `manuscript-fonts.ts`의 Next Font가 웹폰트를 빌드 때 내려받아 사이트에서 제공하며 preload하지 않는다. 선택한 글꼴의 필요한 글자 범위만 로드한다. `--manuscript-font`는 원고 본문에만 적용한다. 글꼴·크기는 현재 브라우저에 저장하고 문서·분할 창이 바뀌어도 유지한다. 공개 페이지·문서의 서식 데이터·내보내기에는 영향을 주지 않는다.

| 요소 | 크기·행간 | 비고 |
|---|---|---|
| 서재 제목 "수록 작품" | 44px (모바일 34px) | 명조 400, 자간 -0.02em |
| 독서 화면 작품 제목 | 40px / 1.4 (모바일 32px) | 명조 400 |

| 첫 문장 발췌 | 20px / 2 | 명조 |

| 소개·설명 | 16px / 1.9 | |

- 독서 본문 글꼴은 색 계열과 관계없이 독자가 고른 명조/고딕(기본 명조)을 따른다. 첫 문장 발췌도 명조로 둔다.

- 영문은 이름에만 쓴다(Orbis Tertius, 표지의 ORBIS TERTIUS).

## 7. 문구

조작법·저장 성공 문구를 화면에 상시 나열하지 않는다. 버튼 이름·아이콘 툴팁·현재 선택·변경된 결과로 설명하고 상세 조작법은 사용자 안내에 둔다. 실패·미전송·충돌·공개 범위처럼 사용자의 판단이 필요한 정보는 표시한다. 문서 정리의 상시 도움말·성공 문단은 제거하며 오류와 정리 되돌리기는 유지한다.

서식 도구는 기존 한 줄 도구 모음의 문자·문단·표·특수문자·목록·검색 팝오버와 크기 입력칸 옆 크기 목록으로 제공한다. 고르기 항목(크기 목록의 숫자, 목록 모양 버튼)은 눌린 상태를 `--sel`·`--sel-ink`로 보여주고 목록 모양 버튼은 실제 표시(•, 가. 등)를 `--link` 색으로 앞에 붙인다. 팝오버끼리는 버튼 한 번으로 바로 바뀌어야 하며, 닫힐 때 원고로 초점을 돌리는 처리가 다음 팝오버를 닫지 않게 한다(`Popover`의 `onReturnFocus`). 원고의 각주 표시 미리보기는 설정 링크 미리보기 카드(`wiki-preview`)를 그대로 쓴다. UI 13/12px·기존 버튼 규격을 유지한다. 특수문자 선택 글리프만 식별을 위해 16px로 표시한다. 셀 경계·열 너비 손잡이·선택 셀과 검색 강조는 본문 편집에 필요한 패턴이며 기존 선·선택·포커스 토큰을 쓴다. 새 바탕색·모양 토큰·고정 막대는 만들지 않는다.

- **슬로건을 쓰지 않는다.** "쓰여진 시간들.", "소설과 그 곁의 세계를 모아둔 서재."처럼 어느 사이트에 붙여도 되는 시적 소개는 지웠다. 홈페이지도 이름과 링크만 둔다.
- **영문 장식 제목을 쓰지 않는다.** FICTION & WORLDS, WORLD BIBLE, DATA USE를 지웠다.
- **실제 데이터로 채운다.** "수록 작품 1편 · 마지막 공개 2026. 10. 2.", "먼 별의 항구 설정집 · 공개 설정 2개".
- **이름:** 공개 목록은 **서재**(도서관 아님), 쓰는 곳은 **집필실**, 목록 제목은 **수록 작품**. 사이트 이름 Orbis Tertius가 보르헤스의 가상 백과사전에서 왔기 때문에 "수록"을 쓴다.
- **문장은 합니다체.** 결과는 과거형 다음에 할 일: "백업 파일을 만들었습니다. 아래 파일 저장 버튼을 눌러 보관하세요." 오류는 무엇이 실패했고 어떻게 하는지: "기기 저장 실패: 저장 공간과 브라우저 설정을 확인하세요."
- **버튼은 짧은 명사·동사구, 마침표 없음:** 작품 읽기, 설정집, 게시 준비, 백업 내려받기.
- **구분은 가운뎃점:** "소설 · 1개 장면", "제1부 · 남겨진 시간". 화살표(↗ →)는 글자로 쓰고 `aria-hidden`을 붙인다.
- 이중 피동(쓰여진)을 쓰지 않는다. 느낌표·이모지를 쓰지 않는다.

**사이드바.** 위에서부터 ◌ Orbis Tertius(홈 링크), 작품 카드(표지·작품명·형식·장면 수·글자 수, 누르면 작품 전환·새 작품·작품 정보 메뉴), 도구(검색 Ctrl K·플롯보드·백업과 복구·가져오기 · 내보내기), 문서 트리(기본 원고·설정집·메모 · 리서치와 사용자 대분류 → 폴더·문서·하위 항목, 원고 상태 점·종류 아이콘), 맨 아래 저장 상태·색 계열·라이트/다크·공개 서재·작품 정보. 새 도구는 `nav-item` 줄로 추가한다.

**편집 패널.** 44px 탭 줄(사이드바·뒤로·앞으로·문서 탭·옆에 열기·참고 패널·더 보기·게시 준비)과 40px 서식 도구(오른쪽 끝에 글자 수와 AI 대화)만 원고 위에 고정한다(84px). 가려진 서식 도구가 있으면 양끝 이동 화살표를 보여준다. 분할 창에서는 도구가 줄바꿈한다. 드물게 쓰는 동작(집중 모드, 순서 옮기기, 복구 지점, 작품 정보)은 **더 보기** 메뉴에 둔다. 원고 위에 고정 막대를 더 만들지 않는다.

**문서 머리.** 분류 글자(부·장 또는 설정 분류) 13px, 제목 입력칸 32px 600, 그 아래 칩(높이 28px, 모서리 6px): 상태(선택 상자), 시점 인물(같은 이름의 인물 설정이 있으면 `--soft` 칩이고 누르면 옆에 열림), 작중 시간, 연결 설정 수, 첨부 수, 속성. 설정 문서는 공개 상태와 등장 수 칩을 둔다. **속성**은 칩 아래에 입력 폼을 펼친다. 새 문서 속성은 이 폼에 넣고, 값이 있으면 칩으로 보여준다.

**문서 통계.** 기존 숫자 자리를 화살표가 있는 버튼으로 바꿔 그 아래 380px 팝오버를 연다(오른쪽 끝 정렬). 본문 선택 시 도구 모음 숫자를 선택 영역 기준으로 바꾸고 ‘선택’을 표시한다. 해제 시 문서 전체로 복귀한다. 표시 기준 선택과 현재 문서·선택 영역·전체 원고 비교 표, 짧은 합계 안내를 두고 세부 집계 규칙은 접힌 **집계 기준**에 넣는다. 표시 단위가 바뀌어도 카세트·사이버의 다섯 자리 카운터 모양은 유지한다. 분할 창에도 각 문서 버튼을 제공한다. `document-statistics.module.css`는 기본 토큰·모양 토큰만 사용하고 키보드 초점은 카운터 안쪽에도 표시한다. 모바일은 팝오버 내부 스크롤과 줄바꿈을 사용한다. [집계·저장 기준](document-statistics.md).

**선택 입력.** 설정의 분류·원고의 시점 인물은 직접 입력 가능한 combobox다. 화살표를 누르면 이미 값이 채워져 있어도 작품의 기존 항목 전체를 펼친다. 입력 중에는 항목을 거르고 위·아래·Enter로 선택, Esc·바깥 클릭으로 닫는다. 새 값도 그대로 저장한다. 목록은 `--pop`·`--line`·`--sel`, 모양은 `--ctl-r`·`--r-in`을 쓴다.

**참고 패널.** 연결·첨부는 300px, AI 대화는 360px(1200px 이하 340px)이다. 900px보다 넓으면 원고 옆에 배치한다. 900px 이하에서는 배경을 가리고 편집 창 위에 겹치며 닫기·Esc·포커스 관리를 지원한다. 700px 이하에서는 편집 창 너비를 채운다. 원고와 나란히 봐야 하는 자료는 분할 편집으로 연다.

**AI 대화.** 패널 위에 현재 문서 제목(15px 600, 넘치면 말줄임. 패널 머리·탭의 'AI 대화'를 다시 쓰지 않는다)·제공자·보낼 자료, 가운데 독립 스크롤 대화 기록, 아래 질문 입력과 전송 버튼을 둔다. 빈 대화에는 '무엇을 도와드릴까요?'와 퇴고·설정 점검·장면 구상·요약·SF 개연성·자료 질문 시작 버튼을 제안한다. 답변은 자동 적용하지 않고 원문·수정안·이유를 비교하는 카드에서 선택 적용한다. 대화는 문서별 작업 데이터로 저장하며 전체 백업에 포함한다. 색과 모양은 기본 토큰만 사용한다.

**AI 설정.** 대화 패널 제목 옆 설정 아이콘과 미연결 안내 버튼에서 기존 Modal을 연다. 제공자·모델 ID, 암호 입력 형태의 API 키, 연결 상태·30일 보관 안내를 한 구역에 두고 시스템 프롬프트를 다음 구역에 둔다. 저장한 키는 다시 표시하지 않는다. 연결 저장과 프리셋 저장·적용은 각 구역에서 동작한다. 프리셋 선택·이름·지침·사본·기본값 재설정, 미저장 전환·삭제 확인과 오래된 편집 안내를 제공한다. 대화창에는 제공자 다음에 빠른 프리셋 선택을 둔다. 선택과 저장 상태를 구분한다. 모바일은 제공자·모델을 한 열로 배치하고 대화상자 내부에서 스크롤한다. 색은 기본 토큰, 완료·오류 안내는 success·danger 토큰을 쓴다.

**설정 링크 미리보기.** 링크에 마우스를 올리면 300px 카드(분류, 제목, 집필용 본문 첫 문단 110자, 옆에 열기, 등장 수)를 링크 아래에 띄운다. Ctrl+클릭도 옆에 연다.

**플롯보드.** 탭으로 열린다. 부와 장(기본)·진행 상태·작중 시간 보기를 전환한다. 열 320px(`--side`), 카드는 상태 점·글자 수·제목·요약·칩(시점 인물, 연결 설정 최대 2개, 작중 시간). 부 보기에서만 **이 부에 장면 추가**와 **부 추가**를 둔다. 같은 부의 장면은 원고 순서가 떨어져 있어도 한 열에 모은다(사이드바의 정리 폴더·부모 문서와는 독립적이다).

**떠 있는 창.** 화면 전체를 회색으로 덮는 `Modal`은 꼭 필요할 때만 쓴다. 고르는 기준:

| 종류 | 쓰는 곳 | 구성 |
|---|---|---|
| 메뉴 (`.menu`, Radix DropdownMenu·ContextMenu) | 문서 트리 `…`·우클릭 | 항목 32px, 아이콘 15px, 구분선 `.menu-separator`. 위·아래·Enter·Esc |
| 팝오버 (`Popover`) | 문서 트리 만들기·이동, 문서 통계, 각주 추가, 설정집 연결, AI 참고 자료, 읽기 설정, 독자 설정 카드, 빠른 메모, 노트 필터 | 누른 버튼·행·선택한 글자 옆에 붙는다. 제목 14px 600, 설명 12px, 폭 280~380px(화면 폭 − 24px 이하), 높이 70dvh 이하 내부 스크롤. 바깥 클릭·Esc로 닫고 초점을 원래 자리로 돌린다 |
| 행 안 편집 | 폴더·대분류 이름 변경 | 행 높이를 유지하는 입력칸. Enter·바깥 클릭 저장, Esc 취소 |
| 대화상자 (`Modal`) | 원고 충돌, 새 대화 확인, 백업과 복구, 공개 판본, 가져오기·내보내기, AI 설정, 새 작품, 작품 정보 | 결정을 강제하거나 내용이 많아 집중해야 하는 작업 |

팝오버와 메뉴는 `--pop`·`--pop-line`·`--shadow`, 모서리 `--r-in`(카세트 6px), 사이버는 배경 흐림을 쓴다. 클래스는 `globals.css` 앞부분에 있다.

노트 메타 항목처럼 단순한 목록·폼은 바깥 `.popover`의 스크롤과 14px/16px 여백을 쓴다. 안쪽 목록에 여백 없는 스크롤 영역을 겹치면 입력·체크박스의 바깥 초점 테두리가 잘린다. 긴 레이블의 체크박스는 `flex-shrink:0`으로 크기를 유지하고 제목만 줄바꿈한다. 기존 `--focus` 강조를 유지하고, 실제 포커스/텍스트 선택·목록 끝으로 이동했을 때도 테두리가 온전히 보이는지 확인한다.

**글꼴.** UI는 `--sans` 13px, 원고는 `--serif` 18px / 2, 폭 680px. 서식 도구에서 원고 표시 글꼴 16종·크기를 바꾸며 본문 서식은 별도 저장한다.

**문서 트리.** `DocumentTree`와 CSS module을 사용한다. 대분류의 `+`는 문서 생성, `…`는 폴더·이름·순서, 문서/폴더 `…`는 하위 문서·폴더·이동 동작이다. 같은 메뉴를 행 우클릭(터치는 길게 누르기)으로도 연다. 메뉴는 행 옆 `.menu`, 만들기·이동 폼은 행 오른쪽(700px 미만은 아래) 팝오버, 폴더·대분류 이름 변경은 행 안 입력칸(Enter 저장, Esc 취소)이다. 접기 화살표와 문서 열기를 나눈다. 왼쪽 손잡이에서 이동을 시작하고 위/아래 경계선은 형제 순서, 행 가운데 윤곽은 하위 위치다. 이동 팝오버에서도 같은 이동을 지원하며 자기 자신·자식으로의 이동은 거절한다.

트리 바탕·선·선택·신호는 `--side`, `--line`, `--soft`, `--brand`, `--danger` 등 기존 기본 토큰을 쓴다. 글자는 UI 글꼴을 따르고 카세트 대분류 번호는 기존 Mono 규칙을 따른다. 깊은 들여쓰기는 세 단계 폭으로 제한해 제목·동작을 남긴다. 손잡이와 `…`는 평소 숨기고 행에 마우스를 올리거나 키보드 초점이 들어오거나 메뉴·폼이 열렸을 때 보인다. 열린 문서 행에서는 흐리게 남긴다. 호버가 없는 기기(`hover: none`)에서는 항상 보인다. 모바일 행은 최소 36px이다. 이동 폼의 긴 부모 경로는 선택 상자 안에 둔다. 폼 Escape는 폼만 닫고 원래 행의 `…`로 초점을 돌린다. 검색 결과에는 상위 경로를 남기며 검색 중 드래그를 막는다. [사용법·데이터 계약](document-navigation.md).

**문서 그래프.** 사이드바의 `nav-item`과 열린 문서 탭에 Network 아이콘으로 들어간다. 플롯보드처럼 편집 영역 전체를 사용한다. 위쪽은 `board-bar` 한 줄(전체/주변 연결 `segmented`, 제목 검색칸, 문서·연결 개수, **필터** 팝오버)이고 주변 연결일 때만 중심 문서·단계 줄이 붙는다. 노드는 문서 아이콘 + 제목 + 원고 상태 점의 칩(높이 28px, `--panel`·`--line`, 모서리 `--ctl-r`)이고 선택하면 `--sel`(사이버는 `--brand` 면)이다. 칩 크기와 글자 12px은 확대율과 관계없이 그대로이고 위치만 확대된다. 문서가 50개를 넘거나 화면 폭이 520px 미만이면 100% 미만에서 선택 문서 외에는 아이콘만 보인다. 선은 본문 링크 실선, 시점 인물 점선이며 같은 두 문서 사이는 한 줄로 그린다(본문 링크 우선). 선택 문서의 선은 `--link`. 범례와 확대 버튼은 지도 아래 모서리에 둔다. 오른쪽 정보 패널은 참고 패널 규격(300px, `--side`)이다. 700px 이하에서는 정보 패널을 지도 아래에 놓고 범례를 숨긴다.

지도 바탕은 `--panel`, 정보 패널·필터는 `--side`, 일반 선은 `--muted`, 선택 문서의 선은 `--link`, 선택 노드는 `--brand`, 글자는 `--ink`·`--ink2`·`--muted`를 사용한다. 컨트롤은 `--ctl-r`를 따른다. 문서 종류는 트리와 같은 아이콘·제목 칩·상태 점으로, 관계는 실선(본문 링크)·점선(시점 인물)으로 구분해 색만으로 뜻을 전달하지 않는다. 별도 주요 버튼을 추가하지 않고 게시 준비가 화면의 주요 버튼으로 남는다. 조작·제목은 기존 집필실 UI 글꼴을 따른다. [상세 사용법](document-graph.md), 구현은 `document-graph.tsx`와 `document-graph.module.css`다.

**개인 노트.** 개인 노트는 사이드바의 기존 segmented로 집필실과 전환하며 같은 RichEditor·doc-head·chip·Popover·DocumentTree·AIChat·저장 상태·ThemeControls를 쓴다. 제목·태그·작품 선택은 선택 사항이다. 노트 아이콘은 메모와 같은 StickyNote, 수집함은 Inbox, 아이스박스는 Snowflake다. 좁은 화면의 노트 트리와 AI 창은 기존 사이드바·참고 패널 서랍과 초점 규칙을 따른다. 노트 트리의 손잡이·메뉴·들여쓰기는 집필실과 같다.

- **사이드바:** 새 노트 → 검색칸과 그 옆 **노트 필터** `IconButton`(SlidersHorizontal, 적용 중이면 `--brand` 6px 점·`aria-pressed`) → 전체·수집함·아이스박스 `segmented` 한 줄(이름 뒤 11px 개수) → 휴지통·백업 → 트리. 태그·작품 select는 필터 팝오버 안에 둔다. 검색 줄 아래 12px을 둔다. 보기·필터를 세로 목록으로 늘려 트리를 밀어내지 않는다.
- **문서 머리:** 칩은 태그(태그가 있으면 `#이름` 최대 3개 + 나머지 수가 칩 글자), 작품 연결, 첨부가 있을 때만 **첨부 n**, 연결 작품 `soft` 칩 순이다. 드물게 쓰는 아이스박스 이동·이미지 첨부·작품으로 가져오기는 맨 끝 `…`(MoreHorizontal 28px) `.menu`에 두고, 메뉴에서 연 팝오버는 칩 줄 아래에 붙는다. 같은 정보를 칩 두 개로 겹쳐 보이지 않는다.
- **본문:** 원고 조판(문단 첫 줄 1em 들여쓰기, 줄간격 2, 문단 아래 1.2em) 대신 들여쓰기 없음·줄간격 1.85·문단 아래 0.6em을 쓴다. 글꼴·크기는 기기 표시 설정을 따른다.
- **빠른 메모:** 집필실 탭 줄의 StickyNote `IconButton`(Alt+N)이 340px `Popover`를 연다. 제목 14px·설명 한 줄, 4줄 textarea, `popover-actions`의 **노트에서 열기**·**수집함에 넣기**(`.button`, 게시 준비가 화면의 주요 버튼으로 남는다). 저장 결과는 `muted` 한 줄(`role=status`)로 보이고 입력칸을 비워 연달아 적게 한다. 화면을 노트로 바꾸지 않는다.
- 브라우저가 예약한 단축키(Ctrl/Cmd+Shift+N·T·W 등)는 쓰지 않는다. [노트 사용법](personal-notes.md).

**휴지통.** 공유 휴지통은 양쪽 사이드바의 Trash2 `nav-item`에서 연다. 기존 `Modal`(검색칸은 `<label>`이 아닌 `div.sidebar-search`)·`sidebar-search`·`reference-card`·`.button`·`IconButton`을 재사용하고 추가 CSS는 배치만 정의한다. 이동은 확인창 없이 처리하고 영구 삭제/비우기 확인은 질문 한 줄과 이력·백업 보존 한 줄로 제한하고, 실행 버튼은 `.button.danger`를 쓴다. [휴지통](workspace-trash.md).

**계정.** 집필실의 로그인 계정 관리는 상단 `IconButton`과 기존 `Popover`·`.button`으로 구성한다. 로그인 화면의 Google 버튼도 `.button`을 사용하며 연결 상태·오류는 13px 토큰 문구를 쓴다. 계정 연결은 원고 도구와 구분해 상단 계정 버튼에 둔다.

## 9. 카세트 퓨처리즘 테마

1970–80년대 녹음기·컴퓨터 콘솔 느낌의 두 번째 색 계열이다. 독자가 공개 페이지 헤더나 읽기 설정에서 고르며, 보라와 마찬가지로 라이트·다크가 있다. 라이트는 베이지 종이(#F5F5DC)에 오렌지(#E5632D), 다크는 콘솔 검정에 밝힌 오렌지다. 캔버스의 Cassette 아트보드 네 개(집필실·독서 × 라이트·다크)가 시안이다.

**주황은 면이 아니라 신호다.** 주황은 주요 버튼 하나, 줄무늬, 선택된 고르기 버튼, 분류 글자, 링크에만 쓴다. 본문·카드·패널 바탕을 주황으로 칠하지 않는다. 베이지 위 넓은 주황 면은 긴 글을 읽는 눈을 피로하게 하고, 주요 버튼과 줄무늬가 눈에 띄지 않게 만든다. 더 강조하고 싶으면 읽는 영역 밖(표지, 헤더 줄무늬, 선택 상태)에서 늘린다.

## 11. 새 기능 체크리스트

- [ ] 0절 표의 기존 부품으로 만들었고 **하지 말 것**에 걸리는 곳이 없다. 같은 종류의 기존 화면과 나란히 찍어 비교했다.

- [ ] 공개 페이지는 `public-site` 안에 있고 헤더에 `ThemeControls`가 있다.
- [ ] 집필실 기능은 8절의 자리(사이드바 도구, 제목 아래 칩과 속성 폼, 참고 패널 탭, 더 보기 메뉴, 팝오버, 대화상자)에 들어가고 원고 위 고정 영역을 늘리지 않았다. 카세트에서 키·LED·Mono 숫자 모양이 필요한지 확인했다.
- [ ] 공개 페이지 색은 `--pub-*`, 집필실·대화상자 색은 기본 토큰만 썼고, 보라·카세트·사이버 × 라이트·다크 여섯 조합을 확인했다.
- [ ] 제목은 `--pub-title`, 분류 글자는 `--pub-kicker-font`, 조작·설명은 `--pub-sans`다. 색 계열 이름으로 분기하는 대신 모양 토큰을 썼다.
- [ ] 버튼 옆 작은 입력·선택은 대화상자가 아니라 팝오버나 메뉴로 열었다(8절 **떠 있는 창**).
- [ ] 주요 버튼은 화면당 하나이고 보라 역할 규칙(2절)과 카세트 주황 규칙(9절)을 지켰다.
- [ ] 슬로건·영문 장식 제목이 없고 숫자에는 단위가 있다.
- [ ] 700px 이하와 360px 폭에서 가로 스크롤이 없다.
- [ ] 새 토큰·패턴을 만들었다면 이 문서와 [변경 기록](../CHANGELOG.md)을 갱신했다.
- [ ] [실제 조작 검증](interaction-verification.md)에 따라 각 변경 도구의 결과와 적용 범위를 확인했다. 선택한 글자와 전체 문서, 기기 보기 설정과 저장되는 서식을 구분했다.
- [ ] 팝오버를 열어 둔 채 다른 도구로 한 번에 전환하고 Esc·바깥 클릭·Tab·편집기 복귀를 확인했다. 선택 범위가 필요한 동작은 실제 선택에서 확인했다.
- [ ] CSS 초기화·전역 규칙을 함께 적용한 화면에서 목록 기호·들여쓰기·표·링크처럼 바뀐 표현을 눈과 계산된 스타일로 확인했다. 버튼·노드가 존재한다는 것만으로 표시 성공으로 판단하지 않았다.
