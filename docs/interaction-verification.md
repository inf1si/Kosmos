# 실제 조작 검증과 구현 완료 기준

기준: 2026-10-04. UI를 바꿀 때 [AGENTS](../AGENTS.md), [유지 규칙](maintenance.md), [디자인 가이드](design-guide.md)와 함께 적용한다.

## 이번 수정에서 배운 점

[main dd8e1fb](https://github.com/inf1si/Kosmos/commit/dd8e1fb9694f1bbf7519d00c174efbaadb817197)는 기존 편집 도구의 크기 선택 목록, 선택한 글자 크기, 목록 기호, 각주 미리보기와 팝오버 전환을 보완했다. 타입·스키마·서식 왕복 테스트가 통과해도 브라우저의 크기 목록이 뜨는지, 전역 CSS가 기호를 숨기는지, 다음 창을 누를 때 초점 복귀가 새 창을 닫는지는 따로 확인해야 했다. 버튼별 단독 확인은 연속 사용의 결과를 보장하지 않는다.

## 구현 전

1. 최신 main 커밋과 현재 작업 기준을 비교한다. 다른 개발자의 변경과 최신 기능 안내를 읽고 보존한다. 게시 직전에도 main이 달라졌는지 확인한다.
2. 바꿀 도구마다 대상·결과·저장 범위를 정한다. 원고 전체의 보기 크기와 선택한 부분의 저장 서식은 서로 다른 동작이다. 기대 동작이 불명확하면 현재 제품 동작과 사용자 요청을 먼저 확인한다.
3. 공용 Popover·표시 CSS·본문 스키마처럼 여러 곳에서 쓰는 부분은 영향을 받는 화면을 목록으로 적는다. 이번 변경과 직접 관련된 흐름을 확인하며 모든 화면을 무조건 반복 검사하지 않는다.

## 실제 사용 흐름

| 대상 | 필수 확인 | 확인할 결과 |
|---|---|---|
| 크기 입력·목록 | 선택 없음 → 목록 열기 → 크기 선택, 실제 텍스트 드래그 → 다른 크기 선택, 섞인 크기·14.5·99·Esc | 목록이 실제로 표시됨; 기기 보기 크기와 선택 서식의 대상이 다름; 잘못된 값은 기존 유효값; 선택과 현재 크기 표시가 일치 |
| 문자·문단 서식 | 적용 → 다음 도구 열기 → 다시 입력 → 실행 취소 → 초기화 | 선택한 글자/문단에만 기대한 결과; 각주·링크 보존; 본문 JSON·화면 결과·초점이 일치 |
| 목록 | 점·번호 표시, 모양 전환, 중첩·해제, 들여쓰기 | 전역 CSS가 적용된 상태에서도 기호가 보임; 계산된 list-style-type·들여쓰기·저장 속성을 함께 확인 |
| 팝오버 | A 열린 채 B 한 번 클릭 → C, Esc·바깥 클릭·입력칸 클릭·Tab | 다음 창 하나만 열림; Esc는 원고로 복귀; 다른 조작을 누르면 그곳의 초점 유지; 선택 필요 동작에서 범위 보존 |
| 각주·설정 링크 | 표시 → 카드 → 카드로 포인터 이동 → 벗어나기, 긴 내용 | 올바른 번호·내용·연결 대상; 카드 유지와 닫힘; 기본 title 중복 없음; 화면 밖으로 잘리지 않음 |
| 표·검색 | 셀 이동·행열 편집·병합 조건·너비 드래그, 결과 이동·치환·취소 | 조작이 본문에 실제 반영; 불가 동작 비활성; 검색 결과·강조 수 일치; 모두 치환은 한 번에 되돌림 |
| 보관·공개 | 변경 → 저장 → 새로고침 → 공개판/백업/교환 왕복 | 해당 형식의 보존 계약에 맞음; 기기 보기 설정을 원고 서식으로 혼동하지 않음; 손실이 있는 형식은 안내와 일치 |

화면 검사는 실제 포인터·키보드로 수행한다. DOM에 버튼이 있다는 확인이나 코드에서 편집기 명령을 직접 실행한 시험은 사용자 조작의 대체가 아니다. 시각 결과는 화면과 계산된 스타일을 함께 확인한다. native datalist 등 브라우저 고유 조작은 실제 목표 브라우저에서 동작을 확인한다.

새 UI와 바뀐 공용 부품은 디자인 가이드의 보라·카세트·사이버 × 라이트·다크, 360px을 확인한다. 좁은 화면에서도 도구로 접근할 수 있고 선택한 크기·팝오버·표가 화면의 조작을 막지 않아야 한다. 터치·다른 브라우저를 확인하지 않았다면 해당 환경은 별도로 적는다.

내용을 바꾸는 시험은 합성 자료나 지정된 시험 작업 공간에서 한다. 운영 점검은 실제 원고·설정·게시를 바꾸지 않는 확인부터 수행한다. 권한·게시·원고 저장이 필요한 시험은 이미 승인된 범위를 따른다. 새 접근이나 사용자 원고의 공개를 단순 UI 검사로 처리하지 않는다.

## 검사와 완료 보고

- 변경한 동작의 경계·저장 계약은 의미 있는 자동 테스트로 확인한다. 브라우저 전환·표시 결함은 실제 조작 결과를 추가한다. 테스트 개수 자체를 완성도의 근거로 삼지 않는다.
- pnpm docs:check는 링크와 문서 갱신 여부를 검사한다. 현재 CI의 타입·Node 테스트·빌드는 이 표의 브라우저 흐름을 자동 실행하지 않는다. 문서 규칙을 추가한 것만으로 자동 UI 검사나 전역 모델 학습을 완료했다고 표현하지 않는다.
- UI·공용 부품 변경 후 위 표에서 해당하는 흐름을 완료해야 UI 검증 완료라고 기록한다. 불가한 확인은 이유·환경·해당 동작을 미검증으로 남기고, 확인한 범위를 넘어 전체 기능 완료로 확대하지 않는다.
- 배포 성공과 운영 동작을 구분한다. 배포 대상 커밋과 CI·배포 링크를 기록하고, 운영에서 실제로 확인한 도구·환경만 적는다.
