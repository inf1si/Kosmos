# 설계 결정 기록

기준일: 2026-10-01. ‘채택’은 현재 설계·구현 선택을 뜻한다. 서비스 계정·유료 결제·운영 배포를 완료했다는 의미가 아니다.

## D01. 개인 작가와 익명 독자

**채택.** 작가 1명의 집필과 작품 공개가 주 목적이다. Auth 사용자 중 허용 목록에 있는 작가만 집필실을 사용하며 독자는 로그인 없이 활성 공개판을 읽는다. 독자 계정·결제·댓글은 초기 범위를 늘리므로 후속 별도 설계로 둔다.

## D02. 집필·독서·설정집을 같은 앱에 둠

**채택.** 설정 ID와 장면 링크·공개 범위를 같은 모델로 관리하기 위해 독립 위키 엔진을 설치하지 않는다. 위키의 검색·분류·백링크 패턴을 사용한다. 현재 공개 설명은 일반 텍스트라 풍부한 위키 본문은 확장해야 한다.

## D03. 집필 단위는 장면

**채택.** SF 출판소설의 구조와 시간·시점을 다루기 위해 장면을 문서로 둔다. 단편은 장 구분 없이 사용할 수 있다. 공개는 선택 장면의 판본을 묶는다. 현재 별도의 회차 객체는 없으며 임의 문장 중간 게시 경계는 지원하지 않는다.

## D04. 공개는 고정 판본

**채택·구현.** 작업본 자동 저장이 독자가 읽는 작품을 즉시 바꾸지 않게 한다. 게시 RPC는 서버에 저장된 선택 장면과 공개 설명을 사본으로 만들고 활성 판본을 원자적으로 전환한다. 새 게시 전까지 초안 변경과 복원이 기존 공개판에 영향을 주지 않는다.

## D05. 설정 본문과 독자 설명을 구분

**채택·구현.** 비공개 기술 규칙·반전·결말과 독자용 설명을 함께 관리하되 공개 payload에는 `publicSummary`만 넣는다. 접기·스포일러 UI는 비공개 접근 제어를 대신하지 않는다. 상세 목표의 독립 공개 위키 문서 편집은 미구현이다.

## D06. Tiptap JSON과 안정된 ID

**채택·구현.** 주석·설정 mark·문단 ID를 보존하려고 구조화 문서를 원본으로 둔다. 제목·서술 문장 변경과 링크 식별을 분리한다. Markdown은 사람이 읽는 내보내기 사본이며 관계를 포함한 복원의 기준은 JSON이다.

## D07. 기기 저장 + 버전 검사형 클라우드 동기화

**채택·구현, 기본 실클라우드 저장 검증.** 텍스트 입력을 기기에 먼저 보존하고 서버 확인 후 동기화 상태를 바꾼다. Realtime은 알림으로 사용하고 실제 버전을 다시 조회한다. CRDT·동시 공동 집필은 초기 범위에 넣지 않는다.

**임시 구현 선택:** 작업 공간 전체 JSON을 저장한다. 첫 흐름을 검증하기 위한 단순한 저장 단위이며 장편의 최종 구조로 확정하지 않는다. 문서별 저장·충돌 UI는 다음 보존 단계에서 확장한다.

## D08. 백업에 실제 첨부와 관계를 포함

**채택·구현.** DB나 파일 URL만 보관하면 첨부가 사라진 뒤 복원할 수 없어 현재·이력이 참조하는 바이트를 ZIP에 넣는다. manifest의 크기·해시·모델 검사를 통과한 파일만 복원한다. 별도 저장소 자동 백업은 아직 연결하지 않았다.

## D09. AI 수정은 제안과 선택 적용

**채택·부분 구현.** 작가의 문체·설정을 유지하고 되돌릴 수 있게 짧은 인용·대체·이유를 제공한다. 저장 판본이 바뀌면 적용을 막고 적용 전 복구 지점을 남긴다. 제공자·모델·실제 품질은 연결 후 정한다.

## D10. Vercel + Supabase 관리형 구성

**채택한 구현 대상, Supabase 초기 설치 완료.** Next.js 호스팅은 Vercel, 인증·DB·첨부·변경 알림은 Supabase를 사용한다. 서버를 직접 운영하는 부담을 줄이는 선택이다. 브라우저는 공개 키와 사용자 세션으로 접근하고 RLS·RPC가 권한을 확인한다. 일반 집필·동기화에는 관리자 비밀 키가 필요하지 않다. 별도 자동 서버 백업만 서버 환경의 service_role을 사용한다. 2026-10-01에 작가 로그인·기본 서버 저장과 Vercel 첫 배포를 확인했다. 오프라인 기기 간 충돌·원격 첨부 복원과 독립 백업은 별도 검증·구현 범위다.

## D11. 문학 서재와 작업 밀도가 있는 집필실

**현재 시각 방향.** 공개 화면은 책 읽기와 작품 제목·본문의 위계를 우선한다. 집필실은 Novela·Muvel·Pensiv의 탐색·분할·참조 패턴을 따른다. SF 특화는 장식보다 시간·인물의 지식·기술 제약·근거 관리에 반영한다. 현재 샘플 테마가 최종 브랜드는 아니다.

## 변경 시 기록

결정을 바꿀 때는 문제·새 선택·원고 및 백업 형식 전환·검증 영향을 이 문서에 추가한다. 현재 선택을 목표 또는 과거 선택과 섞지 않는다. 수행 날짜는 [CHANGELOG](../CHANGELOG.md)에 남긴다.

## D12. 외부 앱은 파일 교환부터

**채택·구현.** Notion·Evernote 계정 전체 권한 없이 ZIP·ENEX·MD·HTML로 이동한다. 미리보기와 분류 후 비공개 문서를 새 ID로 추가한다. 앱 고유 DB·댓글·이력은 복원하지 않으며 전체 원고 보관은 별도의 ZIP 형식을 유지한다.

## D13. 무료 공간 Drive 백업과 최소 OAuth 범위

**사용자 선택·코드 구현, 연결 대기.** 사용자가 무료 저장소를 요청하고 Google Drive 남은 공간 사용에 동의했다. drive.file과 본인 OAuth 클라이언트로 앱 생성 파일만 접근한다. 서버에 저장된 원고·이력·첨부를 ZIP으로 보관하고 실제 읽기 검증 후 성공을 기록한다. 유료 공간 구매·자동 삭제·전체 Drive 접근은 수행하지 않는다.

## D14. AI 제공자 3종을 명시적으로 선택

**사용자 선택·코드 구현, 키 대기.** OpenAI·Claude·Gemini 각각 공식 API 어댑터를 사용한다. 하나의 서버 요청 형식을 임의 URL로 전송하지 않는다. 선택한 제공자만 호출하며 결과·완료 상태를 검증하고 자동 적용 대신 작가 선택을 유지한다.

## D15. Ultra Violet·Very Peri 브랜드와 사이트 전체 라이트·다크

**사용자 선택·구현.** 공개 페이지에 이어 집필실도 같은 토큰과 라이트·다크를 쓴다([D17](#d17-사이드바-하나의-집필실과-부-기준-플롯보드)). 이름을 Orbis Tertius로 바꾸면서 D11의 임시 색(공개 세이지, 집필실 슬레이트)을 하나의 보라 계열로 통일한다. Ultra Violet은 브랜드와 주요 동작, Very Peri는 링크·각주·진행 표시에 쓰고 바탕은 무채색으로 둔다. 공개 페이지는 기기 설정을 기본값으로 하는 라이트·다크 전환을 모든 헤더에 두고, 독서 설정의 배경도 같은 값을 쓴다. 서재·독서의 문학적 레이아웃은 유지하고 슬로건·영문 장식 제목은 실제 데이터로 바꾼다. 카세트 퓨처리즘은 D16, 집필실 개편은 D17에서 이어진다. 규칙은 [디자인 가이드](design-guide.md)에 둔다.

## D16. 독자가 고르는 카세트 퓨처리즘 색 계열

**사용자 선택·공개 페이지 구현, 집필실 미적용.** D15의 보라를 기본으로 두고, 베이지·오렌지의 카세트 퓨처리즘을 두 번째 색 계열로 둔다. 작가가 정하는 사이트 설정이 아니라 독자가 헤더나 읽기 설정에서 고르는 선택이며, 밝기(라이트·다크)와 따로 저장한다. 주황은 버튼·줄무늬·링크 같은 신호에만 쓰고 읽는 면은 베이지·콘솔 검정으로 둔다. 독서 본문 글꼴은 색 계열과 관계없이 독자의 명조/고딕 선택을 따른다.

## D17. 사이드바 하나의 집필실과 부 기준 플롯보드

**사용자 선택·구현.** 상단 헤더, 네이비 아이콘 바, 오른쪽 속성 패널을 없애고 사이드바 하나(작품 전환·도구·부별 원고·설정집·메모·저장 상태)와 편집 패널로 집필실을 다시 구성한다. 원고 위 고정 영역을 줄여 본문이 먼저 보이게 하고, 문서 정보는 제목 아래 칩과 접는 속성 폼으로, 연결·첨부·AI는 필요할 때 여는 참고 패널로 옮긴다. 플롯보드는 진행 상태보다 작품 구조가 먼저 보이도록 부·장 열을 기본으로 한다. 집필실은 공개 페이지와 같은 밝기·색 계열 설정을 쓴다. 카세트에서는 같은 배치에 라벨·LED·하드웨어 키·테이프 카운터 모양을 더하고 배치는 바꾸지 않는다.

## D18. 사이버 색 계열: 라이트는 사이버프렙, 다크는 사이버펑크

**사용자 선택·구현.** 세 번째 색 계열로 사이버를 둔다. 사이버프렙과 사이버펑크를 각각의 색 계열로 나누지 않고 한 계열의 라이트·다크로 묶어, 독자의 밝기 선택이 그대로 두 분위기를 오가게 한다. 두 밝기는 배치와 규칙을 같이 쓰고 모양(알약과 깎은 모서리, 빛번짐, 바탕 무늬, 줄무늬)만 토큰으로 바꾼다. 영문 표시는 사이트 이름과 작품 번호표만 쓴다.
