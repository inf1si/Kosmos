# 글 참조와 백링크

2026-10-25. 노트·집필실의 원고·설정집·메모·분할 편집에서 같은 `@` 도구를 쓴다.

## 사용

본문 문단이나 제목에서 `@` 뒤에 글 이름·작품명·폴더 이름을 입력한다. 계정의 활성 노트와 모든 작품 문서에서 최대 30개를 찾는다. 같은 제목은 종류와 경로로 구분한다. 결과는 왼쪽 정렬한 두 줄 메뉴로 촘촘히 표시한다. 긴 경로는 말줄임하며 마우스를 올리면 전체 경로를 확인한다. 위·아래와 Enter 또는 목록 클릭으로 넣으며 Esc로 닫으면 입력한 글자는 남는다. 이메일의 ASCII 주소 부분과 인라인 코드·코드 블록에서는 열지 않는다. 검색 중 `/`를 입력하면 슬래시 명령 메뉴로 전환한다. 경로는 폴더·작품 이름을 공백으로 나눠 검색한다. 한글 조합을 확정하는 Enter로 항목을 넣지 않는다.

참조는 작은 `@제목` 칩이다. 마우스를 올리면 본문 일부를, 클릭 또는 키보드 Enter/Space로 오른쪽 **연결** 패널에서 미리보기를 연다. **원문 열기**를 눌러야 현재 글에서 이동한다. 도구 모음의 **참조**는 **참조한 글**과 **이 글을 참조한 글**을 보여준다. 모바일은 기존 참고 패널과 같은 서랍이다. 참조 삽입은 실행 취소 한 번으로 되돌린다.

연결은 제목 대신 글 ID로 저장한다. 이름·폴더가 바뀌면 칩과 목록은 현재 제목·경로로 표시한다. 휴지통의 글은 검색·백링크에 포함하지 않고, 기존 칩은 저장 당시 이름과 **사용 불가**로 남긴다. 복원하면 같은 ID로 다시 연결한다. 영구 삭제 뒤에도 자동으로 다른 글에 연결하지 않는다. 현재 글 자체는 검색에서 제외한다.

기존 **설정 링크 추가**와 **노트 링크 추가**는 선택한 글자에 붙이는 `wikiLink` 도구로 유지한다. 공개 설정집 연결과 이번 비공개 참조는 서로 다른 데이터다.

## 저장·발행·내보내기

- 비공개 본문에 `internalReference` 인라인 원자 노드로 `{kind,targetId,workId,label}`을 저장한다. 문서 대상은 작품 ID가 필수이고 노트 대상의 작품 ID는 null이다. 대상 내용은 복사하지 않는다. 제목은 대상이 없을 때만 쓰는 삽입 당시 대체 값이다.
- 원본의 기기 저장·계정 동기화·복구 이력·전체 ZIP/Drive/DB 백업에는 노드를 보존한다. 별도 참조 테이블이나 DB 쓰기를 추가하지 않는다. 백링크는 현재 작업 공간의 활성 글 본문에서 계산한다.
- 발행은 클라이언트 `makePublication`과 서버 `publish_work` 양쪽에서 참조 노드 전체를 제거한다. 제목·대상 ID·작품 ID는 공개 원고 JSON에도 남지 않는다. `publications_no_internal_references` 제약이 누락된 경로의 비공개 노드 저장을 거부한다. 기존 공개 설정 링크는 유지한다.
- 본문 글자 수·원고지·검색·일반 텍스트에는 참조 칩 제목을 더하지 않는다. MD/HTML/ENEX 교환 파일은 참조 칩과 연결 정보를 제외한다. 완전한 참조 보존은 전체 백업으로 한다. 참조를 외부 앱의 링크 형식으로 변환하거나 다시 가져오지는 않는다.
- 묶음 템플릿의 내부 참조는 함께 복제된 대상 ID와 적용 위치(노트/작품)로 바꾼다. 묶음 밖의 참조는 원래 대상을 유지한다. 노트를 작품으로 가져올 때 비공개 참조는 원래 대상에 계속 연결한다.
- `@`를 넣는 동작은 AI 요청을 보내지 않으며 대상 본문을 AI 자료에 자동 추가하지 않는다. 공개 설명·본문에 사용자가 직접 쓴 일반 글자는 비공개 처리 대상이 아니다.

## 배포 순서

앱 배포 전에 [`20261025130617_internal_references.sql`](../supabase/migrations/20261025130617_internal_references.sql)을 적용한다. 기존 `publish_work`의 소유자 확인·권한·공개 순서 처리는 유지하고 본문 복사에 JSON 제거 함수를 넣는다. 제거 함수는 invoker이며 anon/authenticated의 직접 실행 권한은 없다. 제약 추가 전 기존 공개본에 `internalReference` 노드가 없는지 개수만 확인한다. 기존 원고·판본은 다시 쓰지 않는다.

서버 변경은 이전 앱과도 호환된다. 앱만 이전 버전으로 되돌리면 새 노드가 있는 원고를 이전 편집기가 이해하지 못하므로, 해당 원고를 열어 저장하지 않는다. 필요한 경우 전체 백업과 새 노드를 지원하는 버전을 유지한 채 수정한다. 제거 함수·공개 제약은 롤백 때도 유지할 수 있다.

## 후속 작업 조사

| 우선순위 | 후보 | 현재 구조에서 필요한 일 |
|---|---|---|
| 1 | 검색 결과에서 새 노트 만들기 | 기존 `newNote`·`addNote`를 재사용할 수 있다. 검색어를 제목으로 수집함에 만들고, 생성 성공 뒤 검색을 시작한 편집기의 캡처된 범위에 넣는다. 글 전환·저장 충돌·생성 실패 시 잘못된 글에 삽입하지 않는 처리가 선행돼야 한다. 폴더 지정은 다음 단계로 둔다. |
| 2 | 특정 문단 참조 | `StableBlocks`가 문단·제목에 부여하는 `blockId`를 활용할 수 있다. 참조 스키마에 선택적 blockId, 원문 열기의 스크롤·강조, 사라진 문단 표시를 추가한다. 템플릿·노트 복사·가져오기가 blockId를 새로 만들기 때문에 글 ID와 함께 문단 ID 매핑을 보존해야 한다. 문단이 사라지면 문서 전체로 조용히 바꾸지 않는다. |
| 3 | AI에 참조 자료 포함 | 연결만으로 전송하지 않고, 자료 목록에서 사용자가 고른 대상만 포함한다. 전송량·삭제된 대상·권한·출처 표시를 기존 AI 요청 제한과 함께 검증한다. |
| 4 | 많은 글에서 검색·백링크 개선 | 현재는 작업 공간에서 계산한다. 실제 규모를 측정한 뒤 변경된 문서만 재색인하고 최근 사용 순서를 더한다. 지금 단계에서 서버 검색 인덱스나 별도 그래프 DB는 필요하지 않다. |

블록 내용을 본문 안에 펼쳐 동기화하거나 다른 글을 그 자리에서 편집하는 기능은 별도 설계가 필요하다. 현재 구현은 연결·미리보기이며 본문 복제나 공동 편집을 하지 않는다. 위 표는 조사 결과로, 이번 구현에 포함하지 않았다.
