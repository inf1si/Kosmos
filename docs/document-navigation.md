# 문서·폴더 계층과 사용자 대분류

기준: 2026-10-03. 작품마다 독립된 문서 트리를 관리한다. 문서에는 본문과 하위 문서를 함께 둘 수 있고, 폴더에도 문서와 하위 폴더를 넣을 수 있다.

## 사용법

- 사이드바 **문서** 옆 `+`는 **대분류 추가**다. 이름과 기본 문서 종류(원고·설정 문서·메모)를 고른다. 기본 종류는 새 문서를 만들 때의 초기값이며 다른 종류의 문서도 같은 대분류에 둘 수 있다.
- 각 대분류 옆 `+`로 문서를 만든다. 대분류 `…`에서 폴더 추가·이름 변경·위/아래 순서 변경을 한다.
- `…` 메뉴는 행을 우클릭(터치는 길게 누르기)해도 열린다. 만들기·이동은 행 옆 작은 창에서 입력하고, 폴더·대분류 이름은 행 안에서 바로 고친다(Enter 저장, Esc 취소).
- 손잡이와 `…`는 마우스를 올리거나 키보드로 그 행에 들어가면 보인다. 열린 문서 행에서는 흐리게 보이고, 마우스가 없는 터치 기기에서는 항상 보인다.
- 문서나 폴더의 `…`에서 **하위 문서 추가**, **하위 폴더 추가**, **이동 · 순서 변경**을 사용한다. 폴더는 이름도 바꿀 수 있고 문서는 편집기 제목을 직접 바꾼다.
- 접기 화살표와 제목은 별개다. 문서 제목을 누르면 본문을 열고 화살표로 하위 목록만 접는다. 폴더 제목은 하위 목록을 접거나 펼친다.
- 왼쪽 점 손잡이를 끌어 옮긴다. 대상 행의 위쪽 1/4은 **앞**, 가운데는 **하위**, 아래쪽 1/4은 **뒤**다. 대분류 머리 위에 놓으면 해당 대분류의 맨 뒤로 옮긴다. 안내선·테두리로 위치를 표시하며 하위 항목도 함께 움직인다.
- 손잡이를 클릭하거나 키보드로 Enter를 누르면 행 옆에 **이동** 창이 열린다. 상위 문서·폴더·대분류와 맨 앞/뒤/특정 형제 앞 위치를 선택한다. 휴대폰에서도 이 창으로 정리할 수 있다.
- 이동·이름 변경·폴더/대분류 생성·빈 항목 삭제 뒤 **문서 정리 되돌리기**로 마지막 정리 작업 하나를 되돌린다. 이후의 본문 편집과 새 문서는 남는다. 편집기의 본문 실행 취소와는 별개이며 이 정리 이력은 새로고침 후 유지되지 않는다.

기존 원고·설정집·메모 대분류는 유지한다. 사용자 대분류는 최대 40개(기본 세 개 포함), 문서·폴더 노드는 합계 7,500개, 문서는 기존처럼 작품당 최대 5,000개다. 하위 깊이는 24단계까지며 자기 자신·자손·다른 작품으로 이동할 수 없다. 깊은 목록의 시각적 들여쓰기는 세 단계로 제한하고 이동 창에서는 전체 상위 경로를 보여준다. 접힘 상태는 세션 중심이다.

검색은 제목·본문과 폴더 이름을 찾고 결과의 상위 항목을 함께 보여준다. 검색 중에는 결과 경로를 펼쳐 보여주며 드래그는 잠근다. 검색을 닫으면 기존 접힘 상태로 돌아간다. 문서 삭제·휴지통은 아직 없고, 빈 폴더와 빈 사용자 대분류만 삭제할 수 있다.

## 부·장과 발행 순서

**폴더는 집필실 정리용, `chapter`는 독서 화면의 부·장 구분이다.** 폴더 이름·위치를 바꾸거나 다른 대분류로 문서를 옮겨도 `chapter`, 문서 종류, 본문, 각주, 설정 링크, 공개 여부를 바꾸지 않는다. 플롯보드는 계속 `chapter`로 묶는다.

처음 읽는 기존 작업본은 연속된 원고의 부·장 묶음을 폴더로 이어받는다. 같은 부·장 이름이 떨어져 등장하면 각각의 폴더로 만들어 기존 원고 순서를 보존한다. 첫 편집 전에 이를 고정하며 이후 부·장 속성을 고쳐도 폴더가 자동 이동하지 않는다.

저장 시 트리를 대분류 순서 → 형제 순서 → 부모 문서 다음 하위 항목 순서로 펼쳐 `documents[]`에 반영한다. 새로 게시하는 원고 순서도 이 배열의 원고 순서다. 하위 문서는 독립된 문서이며 부모 본문에 합치거나 자동으로 함께 게시하지 않는다. 게시 준비에서 공개할 원고를 각각 선택한다. 이미 공개한 판본은 다시 게시하기 전까지 유지된다. 설정·메모를 원고 대분류로 옮겨도 원고로 변환하거나 자동 공개하지 않는다.

## 저장과 호환성

형식 1의 `Work.navigation` 선택 필드에 저장한다. DB 테이블·문서 ID·IndexedDB 버전은 바꾸지 않는다.

```text
navigation: { version: 1, sections[], nodes[] }
section: { id, title, defaultKind }
document node: { id: document.id, type: "document", sectionId, parentId }
folder node: { id: UUID, type: "folder", title, sectionId, parentId }
```

`parentId: null`은 대분류 최상위다. 노드 배열 안에서 같은 부모를 가진 항목의 순서가 형제 순서다. 모든 부모는 같은 작품·대분류에 있어야 한다. 중복 ID, 없는 문서·부모, 순환, 지나친 깊이를 Zod로 거절한다. 이전 가져오기/오프라인 데이터에 새 문서의 위치가 빠져 있다면 종류에 맞는 대분류 최상위에 보충한다. 자료를 숨기거나 버리지 않는다.

- 클라우드 RPC·기기 저장·복구 이력·Drive 전체 ZIP·R2 DB 덤프에 계층이 포함된다.
- 전체 ZIP은 ID와 계층을 그대로 복원한다. 이전 형식 1 ZIP도 계속 읽는다.
- MD/HTML 교환 ZIP의 `kosmos-transfer.json`에 계층을 포함한다. Orbis Tertius로 다시 가져오면 새 문서/폴더 ID로 재구성한다. 일부 문서만 내보내면 빠진 상위 문서를 건너뛰고 가장 가까운 포함된 상위 항목에 붙인다. 전체 선택 시 빈 폴더·대분류도 보존한다.
- 외부 앱이 이 메타데이터를 해석하는 것은 아니다. 원본 Notion 내보내기의 페이지 계층과 ENEX 노트북 구조를 자동 복원하는 기능은 이번 변경에 포함하지 않는다. 실제 외부 앱의 계층 가져오기 호환성은 별도다.
- 공개 판본에는 폴더·대분류 정보를 복사하지 않는다. 그래프의 본문 링크·시점 인물 관계는 문서 이동 후에도 같은 ID로 이어진다. 트리의 부모 관계를 그래프의 새 선으로 표시하는 기능은 없다.

## 배포와 이전 탭 보호

새 프로젝트에는 `001_studio.sql` 다음 [002_document_navigation_guard.sql](../supabase/migrations/002_document_navigation_guard.sql)을 실행한다. 기존 프로젝트에는 002만 적용한다. 기존 원고·권한·공개판을 수정하지 않으며 반복 적용해도 트리거를 중복 생성하지 않는다.

002는 계층이 이미 있는 작품을 구버전 탭이 계층 없이 저장하려 하면 트랜잭션을 거절한다. 새 클라이언트는 오래된 오프라인 저장 요청·복원본에 계층을 보충해 전송한다. 저장을 거절당한 이전 탭에서 쓴 문장은 먼저 사본으로 보관한 뒤 새로고침하고 최신 원고와 비교한다. 공동 편집·자동 병합을 추가한 기능은 아니다.
