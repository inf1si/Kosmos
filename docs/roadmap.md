# 다음 개발 순서와 완료 기준

상태 기준일: 2026-10-01. 기간·출시일은 확정하지 않았다. 한 단계의 연결 성공을 전체 운영 완료로 해석하지 않는다.

## 단계 0 — 로컬 첫 구현과 문서

**완료:** 집필·기기 저장·충돌 차단·판본·독서·설정·ZIP을 연결한 로컬 앱, TypeScript·빌드·6개 테스트·10개 브라우저 흐름, 인수인계 문서.

디자인은 초기 작동 화면이다. Muvel·Novela·Pensiv 수준의 전체 작업 기능을 완성한 상태는 아니다.

## 단계 1 — 실제 계정·시험 클라우드

**진행 중:** Supabase·Vercel 대시보드 로그인 확인. 기존 빈 Supabase 서울 프로젝트에 SQL 설치, 공개 회원가입 차단과 익명 REST 접근 검사 완료. 작가 계정·허용 목록, Vercel GitHub 연결·환경 변수·첫 배포와 기본 저장·첨부 업로드·게시까지 확인했다. 다른 기기 첨부·오프라인 충돌과 실제 ZIP 복원은 추가 시험한다.

완료 기준:

- 실제 로그인과 허용 목록, Data API·RLS, Storage, Realtime 확인.
- 두 브라우저/기기에서 저장·재접속·충돌·첨부 다운로드 확인.
- 익명·비허용 계정의 초안·설정·첨부 접근 거절.
- 실제 서버에서 판본 생성, 초안 변경 후 공개판 유지.
- 연결 환경과 결과를 검증·변경 기록에 남김.

## 단계 2 — 장편 원고 보존과 백업 보완

시험 클라우드 확인과 병행할 수 있지만 실제 장편 원고를 주 저장소로 옮기기 전에 완료한다.

- 작업 공간 전체 저장을 문서별 저장·버전·변경분 전송으로 확장하고 기존 formatVersion 1의 전환 경로 작성.
- 충돌한 작품·문서·변경 구절을 보여주는 비교·수동 병합 화면 구현.
- 서버 문서 구조·링크 검증 강화, 게시 전 깨진 참조 확인.
- 복원 직후 이력 50개 제한과 동일 ID 원격 첨부 바이트 검사는 구현했다. 미참조 첨부 정리 정책은 남아 있다.
- Drive/S3 서버 백업·일정·저장 후 검증 코드는 구현했다. Google OAuth 연결·실제 일정·복원 훈련, 보관 정책·실패 알림은 남아 있다.
- 실제 장편 규모의 저장·편집·백업 성능, 한국어 조합 입력 확인.

완료 기준은 변경한 문서의 충돌 범위가 명확하고, 양쪽 원고·관계·첨부를 보존·복원할 수 있으며, 브라우저를 닫은 상태에서도 독립 백업이 실행되는 것이다.

## 단계 3 — 운영 배포와 집필 사용감

- Vercel 배포·환경 분리, 기본 URL에서 전체 흐름 확인. 도메인은 이후 연결.
- 실제 원고 한 장과 설정 몇 개를 사용해 문서 이동·분할·검색·속성·게시를 다듬음.
- 문서 삭제·휴지통, 각주 수정, 작업 배치 저장, 부·장 이름 일괄 변경, 플롯보드 카드 이동 검토.
- 공개 홈·작가 소개·작품 소개, 풍부한 공개 설정 문서, 표지·공개 첨부와 철회 관리 설계.
- 공개 판본 캐시를 도입한다면 게시·수정·철회 시 갱신 규칙도 함께 구현.

완료 기준은 첫 실제 작품을 작가가 편집·백업·게시하고, 독자가 모바일에서 각주·설정을 읽으며, 비공개 작업본이 외부 응답에 포함되지 않는 것이다.

## 단계 4 — 첫 실제 AI

- 제공자·모델·원고 전송 범위·월 예산 결정.
- 짧은 장면 검토와 실제 오류·한도·타임아웃 확인.
- 원문 비교, 각주·링크 보존, 이전 판본 제안 차단, 복구 지점 검증.
- 자료 선택 범위와 ‘장면 검토’의 문서 종류 경계 정리.
- 제안별 연속 적용과 검토 결과 기록 개선.

완료 기준은 실제 한국어 SF 원고에서 수정 제안의 품질·근거·비용을 확인하고, 작가가 선택 적용·복원할 수 있는 것이다.

## 단계 5 — 사용 후 확장

시간선·인물 지식·기술 제약·복선, 작품 내 근거 검색, 장편 정합성 작업 큐, DOCX/EPUB, 스포일러 단계, PWA는 실제 사용에서 필요가 확인된 순서로 구현한다.

실시간 공동 집필·결제·독자 계정·커뮤니티는 초기 목표와 별도다. 추가 시 데이터·권한·비용·운영 방식을 다시 설계한다.
