# 노트·문서·작품 공유 휴지통

기준: 2026-10-08. 노트·집필실 행의 `…` 또는 우클릭 메뉴에서 **휴지통으로 이동**을 누르면 확인창 없이 해당 항목을 계정 휴지통으로 옮긴다. 작품 전체는 집필실 홈 작품 카드 우클릭이나 **작품 정보 편집** 창에서 한 번 확인한 뒤 옮긴다(아래 [작품](#작품)). 양쪽 사이드바의 **휴지통**은 같은 목록·개수를 표시한다. 제목·작품 검색, 항목별 **복원**과 **영구 삭제**, 전체 **비우기**를 제공한다. 자동 삭제·보관 기한은 없다.

사이드바와 휴지통 창의 개수는 [공통 표시 항목 계산](../src/lib/workspace-trash.ts)을 쓴다. 폴더 전체 삭제는 내부 문서/노트 수와 관계없이 **1개**, 낱개 문서·노트·작품도 각각 **1개**다. 폴더 행에는 내부 문서/노트 수를 따로 표시한다. 저장 한도 5,000개는 기존처럼 개별 휴지통 사본 수로 계산한다.

## 이동·복원

본문·속성·노트 태그/보관함/작품 연결·첨부·AI 대화와 원래 위치를 함께 보관한다. 하위 노트/문서/폴더는 휴지통으로 같이 이동하지 않고 해당 항목의 기존 형제 위치로 올린다. 작품 사본과 공개 판본은 독립 자료로 유지한다. 마지막 개인 노트와 작품 문서도 옮길 수 있다. 작품의 마지막 문서 이동은 발행 구분이 빈 **새 장면**을 원고 섹션 최상위에 하나 만들며 원래 폴더를 비운다. 복원하면 원본 문서와 새 장면에서 이어 쓴 내용을 함께 유지한다. 빈 폴더/빈 섹션 정리 삭제는 기존 기능이며 휴지통 대상은 노트·문서다.

복원은 해당 항목 하나를 원래 부모·다음 형제 앞에 돌려놓는다. 부모가 없어지면 최상위, 다음 형제가 없으면 형제 맨 뒤에 둔다. 문서의 원래 섹션가 없어졌으면 40개 한도 내에서 다시 만들고 한도에 닿으면 문서 종류와 같은 섹션 또는 첫 섹션을 쓴다. 깊이 24단계를 넘으면 최상위 위치를 시도하며 여전히 유효하지 않으면 휴지통 항목을 유지하고 오류를 표시한다. 하위 항목 중 이전 부모/위치에 그대로 있는 항목만 다시 연결하므로 따로 이동한 항목과 다른 후속 편집은 보존한다.

작품이 없어졌거나 활성 문서·노트·계층·AI 보관 한도에 닿으면 복원을 거절하고 휴지통 항목을 유지한다. 노트의 사라진 작품 연결은 복원할 때 제거한다. 복원한 문서는 트리에서 다시 열 수 있으며 이전 열린 탭·분할 상태는 복원하지 않는다.

## 작품

작품 항목은 작품 객체 전체(문서·정리 구조·AI 대화·이전 판본 기록), 작품 목록에서의 순서, 그 작품에 연결되어 있던 노트 ID를 보관한다. 첨부 메타데이터와 실제 바이트는 그대로 남는다. 이동 전에 서버의 `unpublish_work`로 게시 중인 판본을 철회하고(클라우드 모드에서는 게시 여부와 관계없이 먼저 호출), 휴지통 사본의 공개 판본 연결은 비운다. 이 함수가 없는 서버에서는 작업 공간을 바꾸지 않고 멈춘다. 마지막 작품은 옮길 수 없다(메뉴·버튼 비활성).

복원은 원래 순서 자리(지금 작품 수보다 크면 맨 뒤)에 넣고, 아직 남아 있는 노트에 작품 연결을 다시 붙인다(노트당 100개 한도). 게시는 복원하지 않는다. 작품 수 100개 한도에 닿거나 같은 ID가 이미 있으면 복원을 거절한다. 휴지통에 있는 작품의 문서 항목은 작품을 먼저 복원해야 되돌릴 수 있다. 작품을 영구 삭제하면 그 작품 소속 첨부 목록 중 다른 곳에서 쓰지 않는 것을 지운다. 읽기 사본 `text/trash/<작품 UUID>.md`에는 문서별 `##` 제목과 본문이 들어간다.

## 폴더 전체 삭제

집필실과 노트 트리의 내용이 있는 폴더 메뉴에서 **폴더 전체 삭제**를 선택한다. 질문 한 줄과 **폴더 구조와 하위 문서/노트 n개를 휴지통에 보관합니다** 한 줄, 취소·**삭제** 버튼만 표시한다. 하위 폴더와 문서/노트의 하위 항목을 모두 포함하고 검색·필터에 가려진 항목도 함께 지운다. 취소·Esc는 변경하지 않고 원래 메뉴 버튼으로 초점을 돌린다. 폴더가 사라지면 트리의 추가 버튼으로 초점을 돌린다. 빈 폴더는 기존 즉시 삭제·정리 되돌리기를 유지한다.

질문의 폴더명은 앞 40자로 줄이고 공백 없는 이름도 창 안에서 줄바꿈한다. 저장된 폴더명은 그대로다.

문서와 노트를 기존 `document`·`note` 휴지통 항목으로 각각 보관하며 본문·속성·태그·작품 연결·첨부·AI 대화를 유지한다. 같은 삭제에서 나온 항목은 선택 필드 `folder`(폴더 ID·이름)를 공유하고, 첫 항목의 `folder.nodes`에 삭제한 하위 트리(폴더·문서/노트의 부모와 형제 순서, 이름이 있으면 폴더)를 한 번 보관한다. 새 항목 종류는 아니므로 운영 보호 SQL은 바꾸지 않는다([검사](../tests/workspace-trash.test.ts)). 하위에 문서/노트가 없는 폴더만 지우면 휴지통 항목이 없다. 한 번의 상태 변경으로 전체 하위 계층을 제거하며 휴지통 5,000개 한도를 넘으면 전체 작업을 거절한다. 작품의 모든 문서를 지우면 빈 **새 장면**(발행 구분 없음) 하나를 남기며 노트는 빈 목록을 허용한다. 이미 게시한 판본은 그대로다.

휴지통은 같은 삭제의 항목을 폴더 이름 한 줄(Folder 아이콘, **폴더 · 작품 · 문서 n개** 또는 **노트 폴더 · 노트 n개**)로 묶는다. **복원**은 폴더째 돌려놓는다. 루트 폴더를 원래 상위·다음 형제 앞에 넣고 하위 폴더(빈 폴더 포함)·문서/노트의 계층과 순서, AI 대화를 그대로 다시 만든다. 원래 상위가 없으면 최상위, 깊이 24단계를 넘으면 최상위를 시도한다. 섹션이 없어졌으면 낱개 문서 복원과 같이 다시 만든다. 이미 같은 ID로 있는 폴더(복구 지점 복원 뒤 등)는 다시 만들지 않고, 그 폴더나 영구 삭제로 빠진 문서의 하위는 함께 복원하는 가장 가까운 상위로 올린다. 영구 삭제도 한 줄 단위로 함께 지운다. `folder`를 모르는 이전 버전 탭이 저장하면 이 필드가 빠져 낱개 항목으로 원래 상위 위치에 복원한다. 구조를 보관한 첫 항목만 없으면 남은 항목을 폴더 하나에 평평하게 모은다. 삭제 직전 현재 브라우저에 **폴더 전체 삭제 전** 또는 **노트 폴더 전체 삭제 전** 복구 지점도 저장한다. 그 지점의 복원은 당시 전체 작업 공간을 되돌리므로 이후 다른 편집도 되돌아간다. 최근 50개 이력 보관 한도를 따른다. 저장·복구 지점 생성 실패나 준비 중 작업본·계정·충돌 변경이면 적용을 멈춘다.

## 영구 삭제·비우기

질문 한 줄과 **복구 이력과 백업은 남습니다.**만 표시한다. 실행 버튼은 `.button.danger`(위험 색 글자·테두리)다. 제목은 앞 40자까지 줄여 보여주고 목록에서는 전체 제목을 확인할 수 있다. 취소/Esc는 항목을 유지하고 누른 버튼으로 초점을 돌린다. 삭제 직전에 현재 브라우저에 **휴지통 영구 삭제 전** 복구 지점을 저장하고 저장 실패·준비 중 변경·충돌이면 삭제를 멈춘다. 비우기는 확인창을 열 때 있던 항목들에 적용한다.

선택 휴지통 사본과 더 이상 현재/남은 휴지통에서 사용하지 않는 첨부 목록을 제거한다. Blob/Storage 바이트·복구 이력·이미 만든 ZIP/Drive 백업·공개 판본은 지우지 않는다. 복구 이력 복원은 전체 작업 공간을 되돌리는 기존 동작이며 현재 브라우저·최근 50개 한도다.

## 저장·호환성

`folder.nodes`가 있으면 하나의 루트 폴더·중복 없는 ID·유효한 부모·순환 없는 관계·깊이 24단계를 검사한다. 루트의 삭제 전 외부 부모는 허용하며 다른 노드는 저장된 트리 안에 연결되어야 한다. 손상된 구조는 작업 공간/ZIP 검증과 실제 폴더 복원 직전에 거절한다. 검증을 우회한 작업본도 부모 탐색이 반복되면 멈추며 원본과 휴지통을 유지한다. 구조 필드가 없는 이전 항목은 계속 복원할 수 있다. JSON 형식 버전·운영 SQL은 바꾸지 않는다.

선택 필드 `Workspace.trash`를 기존 계정 JSON·IndexedDB·Supabase RPC/버전 충돌·Realtime·전체 ZIP·Drive ZIP·DB 백업에 포함한다. 최대 5,000개이고 기존 서버 JSON 20MB/계정 첨부 2,000개 한도를 공유한다. 이동 중 첨부 메타데이터를 유지하므로 기존 첨부 수집으로 실제 바이트도 백업한다. 읽기 사본은 `text/trash/<UUID>.md`다. MD/HTML/ENEX 작품 교환에는 휴지통을 넣지 않는다.

trash 필드 없는 이전 백업은 현재 휴지통과 참조 첨부를 보존하고 같은 ID를 활성 자료로 복원한 항목은 휴지통에서 제외한다. 명시된 배열은 빈 배열을 포함해 복원한다. 형식 버전은 1이다. [서버 보호 SQL](../supabase/migrations/20261004104045_workspace_trash_guard.sql)은 기존 배열을 누락한 구버전 탭을 거절하고 ID·사본·위치·첨부 연결을 검사한다. [2026-10-07 마이그레이션](../supabase/migrations/20261007081500_work_trash_unpublish.sql)은 같은 보호 함수에 작품 항목(ID·제목·문서 1~5,000개·순서·노트 ID·첨부의 작품 소속) 검사를 더하고 `unpublish_work`를 추가한다. 앱보다 먼저 설치한다. 이 마이그레이션 전의 탭은 작품 항목이 있는 작업 공간을 읽지 못하므로 새로고침한다. 구버전 탭의 미저장 글은 따로 보관하고 새로고침한다.

## 오래된 저장 대기 요청

휴지통 필드를 빠뜨린 요청의 확정 거절만 호환 복구한다. 서버가 같은 버전이고 휴지통이 비었거나 기기 목록과 같으면 최신 기기 원고를 새 요청으로 저장한다. 다른 휴지통·서버 버전·다른 창의 기기 수정은 양쪽 원고 충돌로 보존한다. 휴지통 보호 SQL·본문·첨부·백업 형식은 같다. [저장 절차](synchronization.md#재전송)·[브라우저 회귀 검사](../tests/browser/sync-recovery.mjs).
